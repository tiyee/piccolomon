本次对应 2026-10-29 审查的 N1 和 R6，以及随后按难度排序的第 1、2 项。

## 列表范围

`ryne-features/src/list_actions.rs` 的 `Extents` 现在借用语法快照中的物理行和代码块目录，
控件生成也借用条目目录；没有列表时提前返回。每个末尾候选行通过有序且不重叠的代码范围
二分查找所属代码块，不再从头扫描全部围栏。

范围结果与旧扫描算法逐项对照：LF/CRLF/CR、多行条目、任务/嵌套列表、引用容器、
反引号/波浪号围栏、缩进代码、未闭合代码、空条目和尾部空行。现有列表动作回归继续覆盖
移动子树、缩进、删除和一次撤销。比较计数仅在测试中启用，生产构建没有计数开销。

规模回归使用 N 个带续行和空行的列表条目，后接 N 个围栏。旧扫描是 `2N²` 个代码范围
谓词；当前二分比较次数被约束在 `2N × (floor(log2 N) + 2)` 内。这里比较算法工作量，
没有据此宣称 GUI 延迟等比例下降。

| 条目与代码块各自数量 | 修复前线性范围检查 | 修复后二分比较 |
| ---: | ---: | ---: |
| 100 | 20,000 | 1,600 |
| 200 | 80,000 | 3,600 |
| 400 | 320,000 | 8,000 |
| 800 | 1,280,000 | 17,600 |

二分后每个候选行至多再检查一个范围是否包含该行；两列不是端到端 CPU 时间。

## 预览候选

`ryne-extensions/src/preview.rs` 保存注册顺序整理好的预览提供者目录。注册表不再为
每个代码块遍历所有非预览贡献。`PreviewCache` 由会话拥有，经 FeatureEngine 的可选
`preview_batch_cached` 接口传入；旧引擎的默认实现清空缓存并走原来的批次接口。

`PreviewProvider::source_cache_generation() -> Option<u64>` 是显式的源码候选契约：

- `None`（默认）保持逐块、按优先级委托。不能擅自缓存依赖选区、显隐或其他现场状态的扩展。
- `Some(generation)` 承诺候选提取是只依赖源码快照及该配置代次的纯计算，允许独立批量采集。
  返回的渲染器实例或影响候选的配置改变时，提供者必须改变该代次。
- 内置 `FencedPreview` 注册后描述符及渲染器实例不变，因此使用 `Some(0)`。
  渲染器输出代次不属于正文提取依赖，JobHost 仍在每次刷新和完成时查询它。

缓存绑定注册贡献 ID、提供者 Arc 实例、完整 DocumentKey 和配置代次。每个提供者最多
保留当前版本的 32 个正候选，不为每个不适用围栏存负条目；整个空结果可以缓存。
源码、配置、实例变化替换旧项，移除提供者清理旧项；键或提取回调失败不缓存结果，
健康提供者继续复用。提取中途失败保留已成功的前缀，并允许健康提供者处理后续块。
生成前后代次不一致也不写入成功缓存。过期语法身份会清空缓存并返回诊断。

缓存命中且全部提供者声明稳定时，只遍历正候选下标的有序并集。存在未知提供者时仍
扫描代码块以执行它，但稳定提供者不重复提取正文。最终仍按源码顺序、注册优先级选择
每块第一个匹配者，并限制 32 块。每提供者只需前 32 个候选：任何更晚候选都有至少
32 个较早匹配块，不论这些块由谁获胜，最终输出均已达到 32 块。

冷缓存会独立提取每个声明稳定提供者的候选，包括可能被更高优先级提供者覆盖的候选；
这是纯计算契约的一部分。缓存的数量边界是每提供者 32 项，不是新增的全局字节预算；
图表资源仍沿用原有每文档 32 块/32 MiB 限制。

## 会话和任务边界

`diagram_views` 与 `preview_at_caret` 共用候选缓存，IME 预编辑期间绕过该缓存。
候选本身不决定显示：JobHost 继续实时检查光标、局部/全文源码、冻结状态、已折叠范围、
取消和文档身份，最终资源键仍绑定贡献、正文、渲染器实例及代次。源码修改后重新提取
范围；相同正文的有效渲染资源仍可按既有协议重绑。导出保持独立快照和原有未缓存接口。

会话回归覆盖：1,000 个普通围栏加一个图表首次提取 1,001 次，后续光标、源码模式及
局部源码切换新增调用 0 次；渲染器代次改变会重新生成资源但不重提取正文。还覆盖
嵌套容器、三种换行、编辑/撤销/重做、预编辑、fork、文档清空、冻结与过期任务取消。
注册表回归覆盖未知提供者持续运行、优先级、32 项合并、源/实例/配置失效、键异常、
中途失败、生成期间代次变化，以及健康提供者隔离。
