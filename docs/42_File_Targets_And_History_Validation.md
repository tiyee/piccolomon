# 第二批：文件目标绑定和历史验证

## N2：保留符号链接的原子保存

`FileStore` 增加有兼容默认实现的 `resolve_path` 和 `write_bound`。
未知/虚拟服务默认以原路径作为身份，沿用原 read/write 命名空间；实际文件服务使用
canonical path。新文件仅允许缺失最后一级文件名，父目录必须存在；悬空链接不视为新文件。

打开时先解析目标、读取实际目标，再检查显示路径的解析结果一致。会话同时保存用户显示
路径和目标路径。普通保存捕获已有绑定，后台请求校验显示路径仍指向同一目标；回执携带
实际写入的目标，匹配当前请求后才更新保存基线和绑定。保存期间继续编辑仍保持 dirty。

AtomicFileStore 在实际目标目录内建立排他的临时文件，原始字节写入、继承权限、sync，
重命名前再次检查显示路径，关闭句柄后原子替换实际目标。读写不会把链接替换为普通文件。
错误时清理临时文件，不更新路径/保存基线，异步失败仍走串行队列的终态回执。

另存为到不同显示路径时，在请求执行时解析并绑定所选目标；选中已有链接则写其实际目标，
选中新文件则使用规范父目录和所选文件名。成功后更新文档显示路径和绑定。重试原路径
仍要求原绑定；若用户希望接受链接的新目标，可以重新打开或另存为到另一条路径。

边界：身份是规范路径，不是 inode/文件 ID。相同规范路径的文件被外部替换或编辑，仍沿用
现有覆盖保存行为；本批没有文件监听或外部内容冲突检测。检查不是文件系统锁，不能保证
针对任意并发/敌对目录替换的无竞争写入；硬链接关系不在保留保证内。Windows 使用相同
服务协议和句柄关闭流程，但本轮符号链接用例仅在 macOS/Unix 验证，不宣称实机验收。
`save_snapshot`/`finish_save` 仍是低层快照/基线接口；直接调用者负责自己的写入和目标约束。

## R1：所有发布共享候选检查，历史策略明确

`publish_plan_inner` 和 `try_undo` 共用 `validate_plan`。结构检查始终执行：

- prepared base 必须匹配当前已提交源码；候选源码和 parse 必须属于同一目标快照。
- anchor/head 必须是有效 UTF-8 边界；closers 必须是非空有效范围。
- 行内、标题和局部源码 Session 必须绑定候选快照并具有有效范围。

历史先准备逆向事务、恢复 checkpoint，再通过功能层准备 Select/RestoreHeading 的最终
显隐状态；不会重跑插入、补全或结构输入规则。验证通过后才同时发布源码、双栈和会话
状态。拒绝或规划/验证器 panic 不改变这些状态，也不通知 DocumentChanged。

新增 `HistoryDirection::{Undo, Redo}` 和 `Validator::validate_history`。默认委托既有
`validate`，因此现有动态约束不再被历史绕过；只用于输入阶段的验证器可以显式覆盖此
钩子，检查方向和计划，或允许已验证历史恢复。豁免策略不能绕过宿主的结构检查。
普通编辑仍调用原 validate，不改变现有输入策略。

`try_undo(redo)` 返回 `Result<bool, String>`：无历史为 `Ok(false)`，成功为 `Ok(true)`，
IME 未确认、规划或验证失败为 `Err`。兼容的 `undo(redo)` 仍返回 unit，但将失败记录到
有界 DiagnosticLog。UI 使用 try_undo 并通过现有七语言 InputFailed 文案显示错误。
Undo 取消预编辑、Redo 先确认预编辑的既有交互保留。

## 验证与保留项

新增回归覆盖：

- 相对/绝对链接、跨目录目标、直接服务写入、新文件、目标目录错误与临时文件清理。
- LF/CRLF/CR、Unicode、保存期间继续编辑、链接排队后改指、悬空链接、恢复目标后重试、
  重新打开接受新目标以及另存为到新文件。
- Undo/Redo 拒绝、验证器 panic、解除限制后重试、默认验证策略、输入策略显式豁免、
  无历史、IME、补全/显隐与局部源码状态的拒绝原子性。
- 功能扩展返回非法历史 closers 时，显式豁免输入策略仍不能绕过结构校验。

架构检查、格式检查、329 项全量测试、配套 stable Clippy 全目标检查以及 diff 检查均通过。
macOS 原生窗口冒烟通过至阶段 374；不等同 Windows 或人工输入法候选验收。
