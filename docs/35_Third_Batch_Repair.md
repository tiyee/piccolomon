# 第三批修复方案与验证记录

## 范围与现状

第三批原定 R9、R10 和贡献者缓存声明。R9/R10 已在第二批实施，本轮保留并重跑其回归；
新增工作聚焦缓存依赖的贡献者隔离，不扩大到 P3–P5 增量解析、虚拟排版或动态插件 SDK。
工作开始时的未提交修改全部保留，不调整依赖或切换分支。

当前 MarkdownFeatures 只要存在任意 additional 模块，就关闭全部正文与控件缓存。
即使该模块只注册命令也会重复生成投影；一个动态控件也会重复生成代码、列表、表格的静态控件。
不能直接删除该保护，否则选区、显隐或配置变化会返回过期结果。

## 修复设计

1. 缓存声明放在实际执行提供者上，注册数量不再决定缓存策略。
   主呈现沿用独占 document 提供者，由该提供者显式返回完整键；未声明者不缓存。
   纯命令、模板、块菜单或预览注册不改变正文键；图表与高亮资源仍由会话独立跟踪。
2. 引入统一的依赖声明与键构建工具：源码身份、源码模式和局部源码范围始终参与；
   提供者显式选择选区、行内/标题显隐和输入补全状态依赖，并给出配置/资源 generation。
   依赖选区的提供者必须包含 anchor/head，不能仅包含无方向的范围。
3. 会话持有单份有界的控件贡献缓存，每个提供者至多一个成功结果。
   缓存身份同时绑定提供者实例与依赖键；未声明、失败或声明回调异常只使该提供者重算。
   校验、源码范围过滤、顺序及命令执行时的重新验证保留。聚合结果在所有分片身份不变时复用。
4. 预编辑不读写持久贡献缓存；全文/局部源码、编辑、撤销、字体、图表及配置代次按声明失效。
   回调前后键不一致时不缓存该结果。故障结果不进入成功缓存，健康贡献者继续服务并记录有界诊断。
5. 保留自定义 FeatureEngine 的旧整体缓存接口作为兼容路径；新增接口默认不缓存。
   不为尚无执行通路的 Decoration 槽增加伪实现；文档明确当前支持的注册层级。

## 验收与执行顺序

- 先补复现：带纯命令模块时，同一源码内移动光标应复用正文及控件；动态控件只调用自己。
- 正式回归使用计数器与独立未缓存结果比较，覆盖声明的各类依赖、未声明者、失效、错误恢复、
  提供者实例更换、配置在回调中变化、空结果、Unicode、LF/CRLF/CR、局部/全文源码、撤销和 IME。
- 扩展不应修改源码、dirty 或历史；执行控件命令时仍检查当前 enabled，不能相信缓存动作状态。
- 专项真实窗口验证纯命令扩展下的布局共享、选区/显隐变化、旧帧拒绝与预编辑；完整冒烟保留前两批覆盖。
- 执行架构检查、fmt、locked 全量测试、当前 stable 全目标 Clippy、完整/专项窗口及失败冒烟。
  用同一计数探针记录修改前后投影和提供者调用次数，不以缓存查询时间冒充 GUI 端到端提速。
- 同步 README、中文 README、AGENTS 和原审查的后续状态，归档实际日志与保留限制。

## 执行结果

### 实施内容

| 边界 | 当前实现 |
| --- | --- |
| 主呈现 | `PresentationProvider::cache_key` 默认 None；Registry 只询问实际独占 document 提供者。Markdown 主呈现声明显隐/有效局部源码和公式代次，不再检查 additional 是否为空 |
| 控件依赖 | `RenderActionProvider::cache_dependencies` 默认 None；`PresentationKey::for_state` 按声明加入有方向的 anchor/head、行内/标题显隐、closers 和 generation；源码、模式及局部源码范围固定参与 |
| 控件缓存 | `RenderControlCache` 由会话持有，按提供者 ID、实例 Arc 和键绑定每个成功结果，保留注册顺序；分片身份相同复用聚合 Arc，空结果也能复用 |
| 故障与校验 | 声明回调 panic 产生诊断并重算该提供者；错误、panic、无效范围/度量、生成前后键变化不缓存；源码与语义快照不一致时清空并拒绝缓存命中 |
| 生命周期 | IME 临时投影绕过持久控件缓存；局部/全文源码、配置、源码和声明的选区/显隐变化按键失效；执行动作仍重新计算 enabled，保留第一批的宿主诊断边界 |
| 兼容与窗口 | 自定义 FeatureEngine 的旧整体接口保留；新接口默认不缓存。应用装配只在 `--smoke-test` 注册纯命令夹具，正常启动无夹具，UI 没有增加对具体功能/渲染器的生产依赖 |

保留已有的单独高亮/图表身份和失败投影不缓存规则，并增加主呈现构建前后键比较，防止生成期间资源代次变化后保存旧键。
实现没有增加新的可编辑正文或改变源码事务、文件保存、PDF 排版、依赖版本。

### 正式回归

测试从第二批的 273 项增至 280 项，新增 7 项：

- 稳定、动态与空控件贡献的独立调用次数及聚合复用；未声明提供者不隐式缓存。
- 三种换行下选区方向、行内/标题显隐、补全状态、配置代次、局部/全文源码及提供者实例更换，与未缓存控件逐项对照。
- 错误、panic、无效度量、声明回调 panic 及生成中代次变化后的恢复；健康提供者持续只生成一次；执行时重新验证 enabled。
- 未声明的主呈现不返回键；声明的主呈现可以表达选区方向与补全输入依赖。
- 语义快照身份不匹配时，已有缓存不能绕过原先的控件校验。
- 带实际命令注册的 Markdown 会话，覆盖嵌套列表/引用、代码、表格、中文、emoji 和 LF/CRLF/CR，核对未缓存投影、撤销与显隐。
  IME 临时结果不复用且不污染稳定控件，取消后恢复原缓存；不产生源码、dirty 或历史变化。
- 主呈现生成期间公式资源代次变化，不会以旧键缓存结果，稳定后才复用。

前两批的字体/图表、高亮延期收敛、故障隔离、PDF 两种编码器、精确 dirty/保存回执及 Unicode/源码映射回归均在全量测试中通过。

专项真实窗口确认实际命令处理器已执行，正文/控件/排版在普通导航和选区变化时共享 Arc；
标题点击展开与局部源码变化拒绝旧帧；预编辑具有有效平台几何，取消后恢复稳定复用及原始 CRLF 源码，dirty/历史不变。

### 保留限制

- 依赖声明是静态提供者的正确性契约；宿主无法发现提供者漏报的外部状态，不构成插件沙箱。
  配置/资源变化必须同步更新 generation，已有缓存存活时不能重复使用指代不同配置的同一代次。
- 未声明的动态分片仍重算；聚合变化可能重建 UI 控件索引和排版。只保证健康分片不重复生成，不宣称任意扩展零成本。
- 缓存对当前注册提供者数量为线性空间，每个提供者最多保留一份结果，另有一份聚合；没有新增字节配额。
  注册本身仍是启动阶段的静态机制，第三方无限量结果及分配失败不在本轮保证内。
- `PrimaryPresentation("document")` 仍独占；代码/列表/引用/表格结构合成仍在 Markdown 主提供者内。
  Decoration 尚无独立组合执行协议，也不支持任意 Widget 或动态加载 SDK。
- 内容编辑/IME 仍全文解析与投影，正文仍全文精排，P3–P5 保留后续实施；没有测量 release P95 或峰值 RSS。
- 实机验证为 macOS；Windows 及真实输入法人工候选窗口仍未覆盖。

### 后续缓存与导出边界

高亮投影在生成前后检查稳定代次；生成期间代次变化或代次回调异常时不缓存，
延期识别完成后仍可缓存。图表任务按注册贡献身份、渲染器实例、代次及正文区分；
缓存持有实例以避免地址重用。交互和导出共用图表尺寸、像素及字节校验。

导出要求功能服务提供冻结快照，不再回退实时服务。内置公式和 Mermaid 提供快照；
当前附加功能模块尚无冻结协议，注册附加模块时导出会明确失败，直到其提供完整的
快照能力。此限制不影响编辑器交互，也不构成动态插件沙箱。
