# 低风险架构修复与验证（2026-10-28）

## 范围

按本轮审查的第一批建议，修复 A3 重复注册、A4 异步保存异常、A8 公式分配扫描，
以及 A7 普通行上下导航。原审查与修复前探针见
[审查报告](reviews/architecture-2026-10-28/report.md)。
保持当前分支与依赖锁定，保留本轮已有审查文件，不修改源码数据模型、Markdown 语义、
历史验证策略、表格导航策略或提供者缓存协议。

## 改动

| 项目 | 实现 | 保持的边界 |
| --- | --- | --- |
| A3 | Registrar 六类执行提供者共用基于 BTreeMap Entry 的插入；Occupied 只返回错误 | 原提供者、注册顺序和 staged 贡献不变；模块处理错误后仍可构建正确 Registry |
| A4 | SaveRequest::run 捕获 FileStore::write 的 unwind 并转为 io::Error，始终生成失败回执 | 普通 I/O 错误、快照身份检查、队列合并、dirty/路径/基线与关闭流程沿用原实现 |
| A8 | 有序折行和公式共用单一推进游标，当前行只遍历属于自己的公式切片 | 保持对象范围、正文 shaping、基线、行高及宽度逻辑；公式归属检查从 O(R×F) 改为 O(R+F) |
| A7 部分 | row_for 与 vertical_target 共用返回视觉行下标的目录查询，普通行直接访问相邻行 | 保留 Upstream/Downstream 的候选顺序、文档边界和原有表格分支 |

这里消除的是重复扫描；普通行导航仍包含目录查询、命中测试与行内 grapheme 定位，
不宣称整个导航为 O(1)。本轮没有进行 release 端到端延迟或峰值内存测量。

## 回归覆盖

- 注册：六类入口均验证失败后原实例/模板及暂存数量不变；模块恢复重复命令错误后，
  Registry 构建成功且实际执行原命令。
- 保存：文件服务首次 panic、后续恢复成功；分别验证已排队保存与失败后手动重试。
  LF/CRLF/CR、中文/emoji，失败后源码身份/字节、路径、dirty、选区和两条历史栈不变；
  成功后基线更新，Undo/Redo 与 dirty 关系保持正确。panic 注入仅在测试运行器中执行。
- 真实窗口：单个 Unicode 长段含 180 个公式，在 80/180/520/760 px 四种宽度下，
  按完整公式包含关系 oracle 核对每行公式、对象范围、资源身份、宽度和基线，
  确认每个公式恰好分配一次。
- 同一窗口按普通视觉行首尾、两个 affinity 和上下方向与旧线性查找 oracle 比较；
  覆盖软折行、空行、公式动态行高、文档首尾和进入表格的边界。表格自身分支保持原实现。
  检查失败返回错误，不把断言 panic 带入原生事件循环。

专项窗口入口：

```sh
RYNE_SMOKE_LOW_RISK_ONLY=1 cargo run --locked -- --smoke-test
```

该专项只证明上述窗口场景，不替代完整冒烟、Windows 实机或真实输入法人工验收。
