# 两项 P1 修复计划与验收标准

日期：2026-10-27。状态：已实施并通过验收，结果与保留限制见
[实施记录](37_P1_Repair_Implementation.md)。下文保留任务划分和验收约定。

问题来源为[当前工作区复查报告](reviews/architecture-2026-10-27/followup/report.md)的
F1、F2。这里的 P1 指审查严重程度，与大文件优化路线中的 P1/P2 阶段名称无关。
实施基线包含当前已有的未提交修改，不能回退或覆盖它们。

## 目标与范围

| 工作项 | 要解决的问题 | 完成结果 |
| --- | --- | --- |
| P1-A | 错误投影通过校验，后续排版可能无法前进或反向切片 | 错误在发布前被拒绝，消费端有可恢复保护，回退源码仍可编辑 |
| P1-B | 块类型查询在普通重绘中扫描全文、分配完整行数组 | 查询使用快照索引，稳定重绘复用块结果，不重复扫描文档结构 |

保留九包依赖方向、源码唯一真相、文档身份、统一事务、IME 临时状态和旧帧保护。
本轮不引入动态插件 ABI、不升级解析器/GPUI/Unicode 依赖，也不实施全文增量解析、
块级正文排版或此前报告中的其他 P2 项。两项 P1 所需的局部代码调整属于本轮范围。

## P1-A：投影不变量与排版前进保护

### A1. 固定复现与消费契约

先把现有独立探针转为生产接口回归，确保旧实现能暴露问题：

1. 从正常表格投影生成 `table.range = 0..0`，原校验会接受。
2. 从三个正常公式生成位置顺序 `[0, 8, 4]`，原校验会接受。
3. 补齐同类变体：逆序/重叠表格、单元格越出表格、重复公式位置、
   重叠公式、空对象范围、表格与图表消费范围冲突。

逐一核对 GUI shaping、`TextLayout::build`、索引发布及两个 PDF 导出消费的前提。
给依赖二分或顺序推进的序列写明顺序与重复值规则；本轮选择**拒绝不符合契约的输出**，
不静默排序、修补范围或重新解释扩展语义。

### A2. 补齐发布前校验

主要修改 `crates/ryne-projection/src/validation.rs`，沿用
`ryne-extensions::project_checked` 的诊断与源码回退，不把业务校验放入 UI。

| 对象 | 必须检查的不变量 | 必须保留的合法情况 |
| --- | --- | --- |
| 所有范围 | UTF-8 边界、上下界和所属源码/展示文本一致 | EOF 锚点和原有 LF/CRLF/CR 映射 |
| 表格 | 展示范围非空、按展示起点严格有序、表格间不重叠；至少有表头行和列；行列维度一致；单元格展示范围包含于该表格范围，源码单元格包含于所属源码行/表格；行和单元格顺序符合消费契约 | 空单元格可为零长度；表头、对齐、转义管道符和 `<br>`；容器内表格 |
| 公式 | 对象展示范围非空、按起点严格有序且互不重叠；范围覆盖当前约定的完整 `OBJECT`；源码/展示范围和对象标记关联一致 | 单元格、列表、引用内公式；公式宽度和基线仍由既有资源度量校验 |
| 图表预览 | 展示范围非空、覆盖完整 `OBJECT`；顺序和唯一位置明确；跳跃消费范围不能与表格/其他图表冲突；资源校验保持既有限额 | 容器内图表、失败后代码回退、折叠/源码模式 |
| 容器与其他视图 | 核实所有后续切片、二分和范围包含的前提；只加强实际消费需要的约束 | 引用嵌套、flow 与容器交叠、表格内公式；空代码块及其锚点 |

表格范围的端点可以等于首末单元格端点；空单元格端点相等不构成非法重叠。
不得对所有类型统一应用“范围不许重叠”：嵌套引用和表格包含公式都是合法的。
也不把 `CodeRowIndex` 已支持的重复/无序输入优先规则随意改成另一套语义。

同一对象关联检查应使用映射区间/事件目录，避免对每个单元格或公式扫描全文 span。
新增有序性及包含关系检查按元数据顺序推进；跨类型冲突采用双游标或区间目录，
不得引入“表格数 × 公式数/图表数”的交叉扫描。

### A3. 在消费端增加前进与切片保护

主要修改 `crates/ryne-ui/src/text_layout.rs`、`layout.rs`、`layout_frame.rs`：

- 表格和图表跳跃前先检查 `next_start > start`、合法边界及范围上限。
  普通文本分支保留处理 EOF 空行的终止条件，不把合法空文档误判为无进展。
- 公式组合在切片前检查 `offset <= next_start <= next_end <= range.end`，
  不用索引 panic 作为错误处理。
- 让排版准备阶段显式返回可恢复错误，或采用等价的受检布局接口；
  不循环重试同一份错误展示模型，不靠 `catch_unwind` 防止无限循环。
- 故障时整次丢弃未完成的行、索引和几何，交由宿主切换到对应投影输入的字面源码回退。
  诊断走已有有界通路；本帧不能混用原投影文字与回退映射。
- 回退必须与当前源码/临时预编辑输入、投影代次及控件空间匹配。
  若需要下一帧才能安装回退，当前帧禁止提交错误几何或接收它的命中；
  安装回退时同步失效相关控件/资源几何，沿用已有旧帧检查。

正常源码回退继续由 `project_checked` 在发布前完成。消费端保护是第二道防线，
不得在每个重绘中重新运行一次全文 `Display::validate`。

### A4. 验证恢复与缓存行为

- 错误输出返回带诊断的 `Display::plain_source`，保留全部源码字节映射。
- 错误结果不得进入成功投影缓存；错误提供者恢复为健康输出后，下一次刷新可重新呈现并缓存。
- 故障不改源码、dirty、路径、选区、历史、源码模式或 IME 预编辑。
- 编辑器和两个导出后端共用发布前约束；导出故障仍保留源码回退，不读取实时可变服务。

### P1-A 验收矩阵

| 编号 | 场景 | 通过标准 |
| --- | --- | --- |
| A-01 | 零长度/逆序/交叠表格，单元格越界，缺行列 | `validate` 返回错误；`project_checked` 返回源码回退和诊断 |
| A-02 | `[0, 8, 4]` 公式、重复/重叠位置、空范围、半个 `OBJECT` | 发布前拒绝；不进入公式反向切片 |
| A-03 | 图表对象范围非法、表格与图表跳跃范围冲突 | 发布前拒绝；渲染资源限额不放宽 |
| A-04 | 测试中绕过校验，直接把异常数据交给受检布局准备 | 返回可恢复错误；不死循环、不 panic、不发布部分几何 |
| A-05 | 失败 → 同一提供者恢复健康，包含可缓存提供者 | 失败不命中成功缓存；恢复后输出正确，随后可以复用 |
| A-06 | 故障前后比较会话快照 | 原始字节、源码身份、dirty、选区、undo/redo、路径和 IME 状态均不变 |
| A-07 | 合法边界语料：空表格单元格、空代码、嵌套引用、表格公式、Mermaid | 正常呈现、编辑和源码映射均保持；不得因过严校验退回全文源码 |
| A-08 | LF、CRLF、CR；中文、emoji、组合字符、ZWJ 和 EOF | 回退与正常投影均保持合法 UTF-8/UTF-16/grapheme 映射和换行字节 |
| A-09 | 错误提供者连续刷新 100 次；之后正常编辑/撤销/保存到临时路径 | 诊断去重且总数不超过 64；交互可继续，保存字节正确 |
| A-10 | 两种 PDF 后端处理正常及异常投影对应的导出快照 | 正常结果保持；异常经同一受检入口回退，导出不挂起、不修改文档 |

A-04 的小故障样本在独立测试进程中运行，父进程每例设置 2 秒截止并可终止子进程。
生产实现必须有前进检查；不能把测试进程超时当作修复本身。
原生窗口只验证已受控的故障回退；不让 `assert!`/`unwrap()` 或人为无限循环进入 AppKit 回调。

## P1-B：块查询索引与稳定重绘复用

### B1. 建立正确性与计数基线

将旧 `block::at` 作为仅测试使用的 oracle，比较完整结果：
`kind`、`range`、`scope`、`anchor` 以及 `None`。不能只比较显示的类型名称。

记录当前 `block::at`、行目录创建、结构索引创建、AST 候选访问和正文布局构建次数。
计数器仅测试/诊断启用，正式默认路径不增加原子计数或计时开销。
沿用原探针数据作为问题证据；性能前后比较另用同机同构建配置重新采样。

### B2. 把全文工作移到快照初始化

主要修改 `crates/ryne-syntax/src/snapshot.rs`、`block.rs`，必要时扩展 `SemanticQuery`：

| 当前操作 | 改造方式 |
| --- | --- |
| 每次 `code_block::lines(text)` | 借用 `parse.semantic().index().lines`，用二分查物理行 |
| 线性查全部代码块/表格 | 使用快照持有的范围/节点目录，保持原来的代码优先、表格其次及 EOF 规则 |
| 按 Item ID 线性查完整条目集 | 复用按 Item ID 有序的既有条目目录，二分定位，无需再建相同目录 |
| 每次遍历列表祖先和找外层首项 | 缓存列表首项/任务目录；外层身份沿当前祖先链查询，代价计入 D |
| 每次扫描 AST 判断任务列表 | 一次计算每个列表直接所属条目的任务状态，不把仅嵌套列表中的任务错误归给外层 |
| 每次重复求容器源码 scope | 共享只读容器/块元数据，保留完整前缀、缩进和物理换行上下文 |

初始化使用一次/常数次线性遍历，利用父子关系传播元数据；不对每个节点重复遍历所有祖先。
已有有序目录可复用，不重复为同一信息保留源码或完整 AST 副本。
新的无序目录排序成本最多 O(K log K)，额外存储 O(节点数 + 条目数)，随快照释放。
冷初始化单独统计，不以“热路径很快”为由隐藏首次打开/首次查询的额外成本。
实施时依据冷查询测量缩小了新目录，避免为所有普通块复制元数据；
这项细化不改变下述复杂度与验收门槛，取舍和原始数据见实施记录。

预热后的查询目标为 O(log N + D + C)：N 为索引规模，D 为当前容器深度，
C 为实际重叠候选数；不能含全文字节数、全 AST 数或总条目数的线性循环。
裸 CR 的规范化语义视图沿用现有身份和等字节映射，不能每次查询重新解析。

### B3. 稳定重绘直接复用块结果

主要修改 `crates/ryne-ui/src/lib.rs`、`interaction_state.rs`、`layout_frame.rs`：

- 增加至多一份当前焦点块的结果缓存，`None` 结果也缓存。
  键至少包含完整文档/源码身份和实际用于查询的 caret。
- 实际 caret 沿用现有规则：正向选区取最后一个被选字符；反向选区取 head。
  不能仅使用 `head`，也不能按旧几何推断源码位置。
- 缓存在选区/源码交互更新时准备，或在第一次需要时惰性建立；预热后的闪烁、
  滚动、焦点显隐和重复 hover 不再重新求同一焦点块。
- hover 结果沿用当前目标优先规则；源码切换、IME、拖选及旧帧抑制继续独立生效。
  不缓存临时预编辑结果来覆盖正式源码结果；相同文字的新文档不能复用旧文档身份。
- 新版本编辑、Undo/Redo、新建/打开、同偏移的块类型变化，都必须使旧结果失效。
  字体、缩放和渲染资源的几何失效继续由原路径负责，不因块结果缓存而绕过。

缓存保存的是语义块结果，不是扩展菜单回调结果，不擅自假定扩展菜单配置永不变化。

### B4. 覆盖菜单打开时的相关查询

`prepaint_frame` 在块菜单打开时调用 `can_insert_above → insertion_context`，
后者仍可能扫描全部 AST。不能只消除 `block::at` 的全文扫描就宣布重绘完成。

复用 B2 的块/容器目录定位插入节点，或为当前菜单目标按完整源码身份及块范围
保存插入上下文/是否允许上方添加的派生结果。新菜单目标、新版本或插入后失效。
仅计算 UI 可用性不提交事务；实际点击仍由当前会话重新校验目标和容器。

### P1-B 性能硬标准

以下是本次修复的拟定门槛，不是既有实测结果或整机帧率保证。

| 编号 | 检查 | 必须达到 |
| --- | --- | --- |
| BP-01 | 同一快照预热后重复块查询 | 物理行数组/共享结构目录重建次数为 0；不重新解析、不全表/全列表扫描 |
| BP-02 | 稳定焦点或空白位置，预热后 20 次光标闪烁/普通重绘 | `block::at` 新增调用为 0；行目录/结构索引/投影/正文布局新增构建为 0 |
| BP-03 | 块菜单打开后，预热并重复相同重绘 | 插入边界可用性查询不扫描全文 AST，不新建完整行数组 |
| BP-04 | 热查询分配 | 无与文档长度成比例的临时分配；允许与实际容器深度/候选数有关的小结果集；不能宣称整个 GPUI 帧零分配 |
| BP-05 | 固定深度语料，64 KiB/256 KiB/1 MiB/10 MiB 的前中后查询 | 记录目录比较/候选访问数；增长符合二分加实际候选数，而不是跟字节数或条目数等比例增长 |
| BP-06 | 同机 release 热查询时延 | 1 MiB 每组 P95 ≤ 0.5 ms，10 MiB 每组 P95 ≤ 1 ms；普通段落、标题、代码、表格、列表、引用组分别满足 |
| BP-07 | 新索引构建/存活 | 当前快照内各目录至多初始化一次；编辑可为新快照重建；旧快照无持有者后新目录可释放，无全局按内容缓存 |

BP-02 在没有输入、后台资源完成、语言识别延期等其他失效事件时检查；
另行触发这些事件确认该重建时仍然重建。不能为了达到 0 次而跳过必要的映射/几何失效。

性能测量方法：

1. 同机同 Rust、locked release 构建，修复前后各运行相同驱动；编译完成后单独测量。
2. 六类语料各测 64 KiB/256 KiB/1 MiB/10 MiB；固定嵌套深度，另设深度压力组。
   小代码块、多独立表格、多条目列表必须确实增加块数，不能只增长单个正文字符串。
3. 每个位置预热 100 次，再记录至少 1,000 次单查询样本；执行 3 轮，保留各轮 P50/P95/P99。
   使用 black_box 消费完整结果，构造/解析/首次索引成本单独测量。
4. 先过 BP-01–BP-05 的结构与计数门槛，再判断 BP-06。
   若环境噪声无法满足时延门槛，记录失败与原因，不将 debug 数字或批次均值当 P95 替代。
5. 记录目录大小/估算字节与首次构建耗时；额外内存随语料规模线性增长。
   不以这项局部查询验收声称 10 MiB 输入或 GUI 总 RSS 已达标。

| 4 | B2 快照索引与语义查询 | syntax | B-01–B-06、BP-01/BP-04/BP-05/BP-07 通过 |

| 6 | 独立性能复测、完整回归和文档同步 | 测量驱动、smoke、实现记录 | 全部门槛通过，关闭 P1-B；提供原始证据 |

建议按上述边界形成可单独审查的提交；P1-A 的安全约束先于 P1-B 的性能缓存。
不能以性能优化掩盖非法投影，也不能以删除旧帧校验换取缓存命中。

## 最终验收与交付证据

实施完成后运行：

```sh
python3 scripts/check-architecture.py
cargo fmt --check
git diff --check
cargo test --locked
cargo clippy --locked --all-targets -- -D warnings
cargo run --locked -- --smoke-test
cargo run --locked -- --smoke-test-failure
```

失败注入冒烟预期退出码为 1，其他检查预期为 0。若本机 Clippy 命中旧驱动，
使用已安装的匹配 Rust 驱动并记录绝对路径，不修改全局配置。

新增 P1 窗口专项应覆盖受检回退、恢复后的命中与 IME、闪烁/滚动复用、
菜单打开时复用以及同偏移新源码失效。专项入口及具体计数输出随实现记录交付；
现有 `RYNE_SMOKE_PERFORMANCE_ONLY` 不能替代这批新增断言。
所有 native callback 的检查失败都正常报错返回，不让 panic 穿过事件循环。

交付证据包括：

- 本文每个 A-/B-/BP-编号对应的测试或测量入口与结果；未通过项不能标记已完成。

- 最终源码变化、兼容性影响、索引空间及未解决限制的实现说明。
