# 第一批修复方案与验证记录

范围：2026-10-27 审查的 R1（局部源码控件缓存）、R2（识别收敛）、R7（扩展故障边界）、R8（观察者和诊断）。
保留现有工作区修改、依赖锁定、源码事务及原始换行；第二批扫描与增量解析不在本轮范围。

## 设计与验收

### R1：明确控件缓存依赖

- 将匿名元组替换为具名控件缓存键/条目，包含源码身份、全文模式和局部源码范围。
- 更新 `cache_source_controls` 的契约；未声明稳定依赖的扩展、IME 和故障结果继续不缓存。
- 验收：列表/任务标记、嵌套表格、代码入口的局部源码进入、切换范围、退出均与完整重建一致；
  相同键复用 Arc，视图变化不修改源码、选区、dirty、撤销或重做。

### R2：保证有界处理能够结束

- 识别结果使用独立目录，最多 4096 项及 2 MiB 正文键；不再与最多 64 项的高亮缓存共用容量。
- 本轮访问过的识别结果不被本轮后续块淘汰；资源不足的正文稳定保留普通样式，不标记为等待。
  不在当前文档使用的条目在轮末清理，编辑和块移动可继续复用相同正文结果。
- 每轮最多八次识别，并共享 50 ms 识别耗时余额，各次请求将剩余余额转换为协作式截止时间。
  前面块的高亮、源码复制或映射不消耗识别余额，避免每轮都在到达后续自动块前耗尽预算。超时识别为缓存的普通样式结果。
  该预算仅约束语言识别，不承诺同步 Tree-sitter 高亮或全文投影的总耗时。
- 为高亮端口增加默认关闭的待处理查询；UI 只为明确声明待处理的服务调度一个延后任务。
  不依赖光标闪烁驱动处理；任务绑定源码身份，文档替换、IME、拖选和失效任务不发布旧状态。
- 验收：8/64/80/128 个不同正文在有限轮内结束并允许投影复用；容量和字节上限之外也能结束；
  重复正文、失败结果、移动、编辑、撤销、三种换行保持正确。真实窗口无需额外输入即可完成后续轮次。

### R7：统一运行时回调边界

- extensions 提供共享、有界、线程安全诊断记录及 FeatureEngine 宿主适配器。
  session 保留原服务用于新建文档，实际运行使用当前文档独立的适配器，避免 fork 重复包裹及共享故障状态。
- 预览新增带诊断的批次接口（默认兼容旧实现）。注册表逐提供者捕获 `input` 故障，继续其他提供者；
  同一轮故障提供者不对后续块重复调用。外层自定义 FeatureEngine 仍由宿主捕获。
- 块 UI、源码范围、插入模板、快照、缓存声明等 getter 使用明确回退；主投影沿用既有校验与原文回退，
  不能把故障回退写入成功缓存。图表 generation 在任务创建和完成时都捕获故障。
- 验收：输入、代次、菜单和快照故障不越过会话边界；健康预览仍可排队，故障块保留可编辑代码；
  导出不改变实时文档，回调失败不产生内容历史。此边界不处理 abort、内存耗尽或形成插件沙箱。

### R8：停止重复故障并统一诊断

- 观察者注册时分配可识别身份；首次 observe panic 后停用该注册实例，继续通知健康实例。
- 所有故障通过同一记录入口：最多 64 条、去重，身份/消息限制 256/4096 字节，并释放过大的 String 容量。
  读取日志返回拥有值快照，不向调用者暴露可变 Vec。
- 验收：提交后观察者失败不回滚，撤销/重做仍可用；100 次后续选择不重复调用失败实例；
  多个失败/健康实例互不影响，诊断条数和单条大小均有界，UTF-8 截断合法。

## 执行顺序

1. 先补正式回归以复现缺陷，再实现 R1 和统一诊断/回调边界。
2. 实现识别目录、预算与 UI 后续任务；补无窗口和真实窗口回归。
3. 检查本轮 diff；运行架构、fmt、全量 locked 测试、当前 stable Clippy、完整窗口冒烟和失败冒烟。
4. 更新中英文 README、AGENTS 当前状态与本文件验证记录，保留审查原始证据。

## 执行结果

四项修复已实现，生产实现涉及 extensions 的诊断/宿主适配器和预览批次、services 的识别目录/预算、
session 的控件缓存/观察者/任务代次检查，以及 UI 的单一后续任务。没有调整依赖版本。

### 修复前后证据

| 场景 | 修复前 | 修复后 |
| --- | --- | --- |
| 进入列表局部源码 | 缓存 3 个控件，完整重建 0 个 | 缓存与重建均为 0 |
| 退出列表局部源码 | 缓存 0 个控件，完整重建 3 个 | 缓存与重建均为 3 |
| 80 个不同自动代码块 | 第 10 轮后回落到 64，16 轮仍未结束 | 第 10 轮完成 80/80，后续保持稳定并允许投影复用 |
| 预览提供者 panic | 越过会话边界 | 被隔离，健康提供者继续排队 |
| 失败观察者后的 100 次选择 | 反复调用并追加诊断 | 只调用失败实例一次，保留一条诊断；健康实例继续通知 |

正式回归补充了嵌套容器、三种原始换行、选择/dirty/历史保持、8/64/80/128 块收敛、
识别条数/字节耗尽（以缩小容量覆盖边界）、剩余额度耗尽与恢复、移位/编辑/撤销、运行时 getter/快照失败、
图表代次在创建/完成时失败、多个观察者故障和诊断 UTF-8/保留容量限制。
既有观察者用例改为确认“失败后不再次通知”，没有移除提交与撤销的验证。

### 验证

- 架构检查、fmt、`git diff --check`：通过。
- `cargo test --locked`：266 项通过（原基线 255 项，新增 11 项）。
- 当前 stable 的全目标 Clippy 零警告检查：通过；使用
  `/usr/local/opt/rust/bin/cargo-clippy clippy --locked --all-targets -- -D warnings`，未改全局配置。
- 第一批真实窗口专项：通过。128 块无需输入即可完成后续识别；空闲投影保持资源身份；
  局部源码控件恢复、IME/拖选延后、文档替换取消旧任务，以及源码/历史不变均经窗口检查。
- `cargo run --locked -- --smoke-test`：完整 macOS 窗口冒烟通过，退出码 0，包含原有全部回归及第一批检查。
- `cargo run --locked -- --smoke-test-failure`：按预期报告检查失败并返回退出码 1，没有 panic 穿过 AppKit。

专项入口：


### 保留边界

本机验证为 macOS，不代表 Windows 桌面或全部输入法人工验收。
语言识别仍为有预算的同步工作，后续任务也在 UI 线程生成完整投影；未把总刷新耗时承诺为 50 ms。
超时、有歧义和资源容量外的正文保留普通样式；此轮未实现后台增量高亮、增量解析或块级精排。
第二批的删除重复投影、鼠标/方向键扫描和混合表格平方扫描未改动。
