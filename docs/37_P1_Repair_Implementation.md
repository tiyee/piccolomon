# 两项 P1 修复实施与验收

日期：2026-10-27。对应[修复计划](36_P1_Repair_Plan.md)和[复查报告](reviews/architecture-2026-10-27/followup/report.md)的 F1/F2。
本文中的 P1 是审查优先级，不是大文件优化阶段名称。

## 实现

### 投影与排版安全

`Display::validate` 补齐表格行/单元格的源码包含关系，并调用共享的 `validate_layout`：

- 表格必须有非空消费范围、表头和列，按展示位置有序且互不重叠；行列维度匹配，
  单元格包含于所属表格且保持顺序。空单元格仍可以是零长度范围。
- 公式与图表必须覆盖完整 `OBJECT`，位置唯一、有序且不交叠；对象视图与带 math/diagram
  样式的源码映射 span 双向对应。缺少视图、缺少标记、范围不符均拒绝。
- 图表不能与表格或公式争用展示消费范围；容器缩进等几何输入设有边界。
  表格包含公式、嵌套引用和 flow 交叠仍合法，不统一禁止所有区间交叠。

校验拒绝时继续走 `project_checked` 的字面源码回退和有界诊断，失败不进入成功投影缓存。
对象检查使用顺序游标，不按每个对象扫描所有 span/所有表格。
共享打印布局入口也执行同一结构校验，两个 PDF 后端直接收到未经校验的非法模型时返回错误；
应用的导出快照仍在此前受检发布步骤保留原始源码回退。

`TextLayout::build` 改为返回可恢复错误，在实际重建布局时检查共享结构契约；
缓存命中的重绘不重复校验全文。表格/图表跳跃使用 `checked_layout_advance`，
公式 shaping 在切片前检查当前范围与对象顺序，EOF 空行保留独立终止条件。

消费端失败时，整次放弃未完成的布局，清除旧控件、图表图像、菜单和几何，
使对应的成功投影缓存失效，然后为当前投影输入构建字面源码回退。
预编辑期间使用临时文本；不把临时范围套到已提交源码。回退保持可编辑并重新绑定本帧代次。
若回退布局仍失败，发布无可命中行的不可用占位，旧几何不能继续解释输入。
所有原生回调中的失败正常报告/返回，不借助 panic 退出事件循环。

### 块查询与稳定重绘

`block::at` 复用代码/表格缓存的有序目录及共享 AST 范围、物理行索引，
不再扫描全部代码块、表格或创建完整物理行数组。条目 ID 使用既有有序条目目录二分查找。
快照仅新增列表首项/直接任务类型目录，容器上下文沿当前祖先链查询；
热查询复杂度保留为 O(log N + D + C)，其中 D 为容器深度，C 为实际候选数。

这是对计划 B2 的实现细化：没有给每个普通块复制完整 Block 或缓存所有节点的祖先结果。
首次试做的全块目录会增加新快照的构建成本；最终采用较小的列表目录，
普通块借用已有 AST 和行索引。该取舍保留计划允许的 D 项，减少冷查询及额外记录占用。

插入边界使用同一个语义范围目录（加入 List 节点，块类型查询仍保持原过滤规则），
不再扫描整个 AST。首个非空白位置随共享索引记录，判断“在上方添加”无需重复检查全文前缀。

UI 保存一份焦点块结果和一份菜单插入可用性结果，连 `None` 也缓存；
键绑定完整源码身份、实际选区查询位置/块目标。正向选区取最后一个被选字符，反向选区取 head。
编辑、Undo/Redo 或换文档后的旧键不能命中；扩展菜单回调、字体/资源几何和旧帧检查仍独立运行。

新增 `query-metrics` / `p1-metrics` 为显式诊断 feature，默认构建没有查询计数或计时开销。
旧块算法只保留为测试 oracle；新查询不双算。

## Release 查询测量

本机 x86_64 macOS、Rust 1.99.1、locked release。构建结束后单独测量，
没有并行运行本次 GUI 或其他基准。实际字节数略高于配置大小，以重复完整语料为单位。

最终六类语料 × 四种规模 × 前中后三位置 × 三轮，共 216 组、216,000 次采样；
每位置预热 100 次，每组 1,000 个独立单次样本，记录 P50/P95/P99。
含很多独立代码块、表格和列表条目；另有固定 16 层列表/引用的 1/10 MiB 压力组。
每组均通过计划的 1 MiB P95 ≤0.5 ms、10 MiB P95 ≤1 ms 门槛。

下表单位为毫秒。修复前是文末查询 P50（每组 30 样本、一轮），
修复后是前中后三位置、三轮中**最差 P95**；两列统计口径不同，不用于计算加速倍数。

| 语料 | 1 MiB 修复前 P50 | 1 MiB 最终最差 P95 | 10 MiB 修复前 P50 | 10 MiB 最终最差 P95 |
| --- | ---: | ---: | ---: | ---: |
| 普通段落 | 2.837210 | 0.000427 | 31.707842 | 0.000370 |
| 标题 | 2.938777 | 0.000446 | 41.414917 | 0.000400 |
| 代码 | 0.124827 | 0.000171 | 5.899888 | 0.000159 |
| 表格 | 0.241486 | 0.000153 | 2.019729 | 0.000219 |
| 列表 | 0.529228 | 0.000651 | 7.944036 | 0.000841 |
| 引用 | 4.424361 | 0.000503 | 52.154571 | 0.000677 |

六类普通语料单次热查询累计分配最多 32 字节；16 层压力组最多 480 字节，
最差 P95 分别约 0.001676/0.001577 ms。两种规模下目录和物理行数组的热重建次数均为 0。
这些是局部查询数据，不是 GPUI 帧耗时、输入到显示延迟或整个窗口零分配保证。

冷查询仍包含首次语义索引和结构缓存初始化。10 MiB 六组冷查询约为：
段落 64.50 ms、标题 83.23 ms、代码 425.34 ms、表格 434.11 ms、列表 1243.99 ms、引用 141.00 ms。
全文解析另计，原始数据保留；不能将热结果解释为新文档首次查询也已微秒完成。
新增列表记录在约 1/10 MiB 列表语料中为 33,827/338,252 项，记录 payload 约 0.81/8.12 MB，
不包括 B-tree 节点管理开销和既有语义索引；没有把它当作总 RSS 测量。

## 保留限制

- 内容修改、Undo/Redo 和预编辑仍全文解析/投影，正文仍全文精排；新版本允许重建相应目录。
- 未实施 F3–F7 的其他 P2 项、开放装饰协议或额外模块的导出快照协议。
- 查询计数是同线程诊断，分配计数只包含独立驱动标记的热查询，不是整进程采样器。
- 原生验证为 macOS，没有新增 Windows 实机或人工各输入法候选窗口验收。
