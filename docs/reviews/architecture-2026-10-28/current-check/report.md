## 扩展协议与逻辑边界

**R1：普通编辑和历史恢复的验证协议不同。**
[undo:452](../../../../crates/ryne-session/src/lib.rs#L452) 绕过
[普通发布验证:216](../../../../crates/ryne-session/src/lib.rs#L216)。探针让验证器拒绝修改后，
普通输入被拒绝，Undo/Redo 仍改变正文，验证器调用增量为 0；历史路径也没有完整复用
closers 和显隐 Session 的候选一致性检查。这会阻碍只读策略、动态文档约束等扩展。
当前证据不意味着内置撤销已损坏用户文档。

建议将始终执行的结构一致性校验与可配置的策略校验分开，发布来源明确区分
Edit/Undo/Redo。历史恢复不重新运行输入补全；验证器显式声明是否约束历史。
拒绝必须保留源码、双栈、选区及显隐状态，并返回可报告错误，不能静默失败。

**R2：控件提供者的身份回调突破局部隔离。**
[render_actions.rs:217](../../../../crates/ryne-extensions/src/render_actions.rs#L217) 在局部捕获之外
调用 `id()`；缓存、诊断及动作查找也反复读取身份。探针中一个提供者在注册后身份回调
panic，导致整批返回错误，健康控件一起消失。外围保护能阻止该 panic 直接逃出，问题在
故障隔离粒度。建议注册时固定 ID、命令目录和实例句柄，运行时不再重新询问身份。
验收覆盖缓存/未缓存、生成/诊断/执行路径，健康提供者必须继续可用。

**R9：后台操作没有统一终态保证。**
[打开文件](../../../../crates/ryne-ui/src/files.rs#L171)、
[导出](../../../../crates/ryne-ui/src/export.rs#L119) 和
[检查更新](../../../../crates/ryne-ui/src/menus.rs#L203) 直接调用可替换服务，操作标志在
await 正常返回后才清理。服务 panic 时没有统一的失败回执；普通 `Result::Err` 已有处理，
不能混为一谈。已修复的保存队列本次探针仍能清除 saving 并派发后续保存，不在此问题内。
建议复用保存的任务边界模式，结果携带操作身份，集中处理成功、失败、取消和过期结果。
本次未在 AppKit 回调内注入 panic，也未证明内置普通 I/O 错误会卡住操作。

## 后续扩展最容易遇到的限制

这些是能力演进建议，不额外计入缺陷数。

1. **按贡献冻结导出依赖。** [snapshot:78](../../../../crates/ryne-features/src/lib.rs#L78)
   对任何 additional 模块都返回 None，纯命令或控件模块也会使 PDF 导出不可用。
   可以声明「不参与导出」「可冻结呈现」「不能冻结」，只检查实际影响输出的依赖。
   回归目标：增加纯命令模块后 PDF 仍可用；影响呈现但无法冻结的模块仍明确拒绝。
2. **把已声明的装饰变成可组合的执行协议。** `Slot::Decoration` 目前没有通用执行入口；
   [BlockContribution](../../../../crates/ryne-features/src/presentation/contribution.rs#L10)
   还是 features 内部实现，主文档呈现仍独占。新增范围装饰需明确冲突顺序、映射归属、
   缓存依赖和导出等价性，继续只生成一份源码映射。
3. **块菜单扩展仍受封闭类型限制。**
   [block_ui 注册](../../../../crates/ryne-extensions/src/registry.rs#L92) 强制独占，
   内置菜单占用此槽；`BlockCommand`、`InsertBlock` 也是封闭枚举。当前更擅长添加围栏预览、
   结构控件或处理已有编辑意图，尚不是任意块/菜单扩展 SDK。若出现具体新菜单需求，
   可开放受验证的命令 ID 与声明式菜单贡献，不必为此先设计动态插件 ABI。
4. **让 SemanticQuery 成为实际使用的边界。**
   [ParseSnapshot 的 Deref](../../../../crates/ryne-syntax/src/snapshot.rs#L24) 仍允许功能层直接
   遍历 AST。R4 表明已有索引并不能自动阻止新代码重扫。先补齐常用的围栏、祖先、容器和
   局部范围查询，再逐步迁移热点；不应一次隐藏所有解析器类型而制造大范围改动。
5. **单目标操作验证不应强制重建全部控件。**
   [动作执行](../../../../crates/ryne-extensions/src/render_actions.rs#L343) 为检查一个动作，
   重建该提供者全部 controls。可以增加针对 target 的可用性查询，默认保留全量验证兼容
   未迁移提供者。仍需校验当前文档身份、范围和 enabled，不能信任旧菜单状态。
6. **历史与缓存需要可观测的内存账目。**
   [core 历史](../../../../crates/ryne-core/src/lib.rs#L119) 没有条数或字节预算，大量替换的
   逆向正文会持续保留；高亮缓存的 2 MiB 也主要计算正文，不含全部 spans/容器开销。
   先记录历史字节、缓存资源、活跃快照和峰值内存，再设计用户可理解的裁剪策略。

## 实施顺序和性能验收

第一步独立修 R3/R4，并把现有复现转成维护性回归。第二步明确 R1/R2 的协议、统一 R9
后台终态。第三步拆分 R5 的失效范围、缓存 R6 候选并索引 R8 导航；R7 另做调度和
生命周期设计。以上都可以保留当前分层，不要求先重构整个编辑器。

随后再做大文件 P3：块级排版复用、可见块精排和高度索引。内容修改仍全文解析/投影，
IME 临时状态仍创建完整临时源码并解析，正文仍全文精排；已有视口绘制与光标缓存没有
消除这些成本。保守局部语义/投影及局部 IME 可作为 P4/P5，继续保持单一源码与版本映射。

建立独立 release 场景基准：普通段落、多小围栏、单长代码、长表格、嵌套列表/引用、
密集公式；分别测首中尾编辑、导航、滚动、预编辑以及 LF/CRLF/CR。记录输入到显示的
p50/p95/p99、parse/project/layout/paint、布局构建次数、提供者调用数、命中率和峰值内存。
不要把完整 smoke 中混合场景的分位数当作大文件输入延迟基准。
