# 详细设计

[返回总览](README.md)。本文的数据结构和接口均为拟议契约，不表示已存在的 API。

## 1. 数据模型与所有权

| 数据 | 职责 | 所属层 |
| --- | --- | --- |
| `Source`、事务、历史 | 原始 Markdown 字节、文档版本、已提交选区、保存基线 | `ryne-parser` 提供源码原语，`ryne-core` / `ryne-session` 管理发布 |
| 语义区块树 | 标题、段落、列表、引用、代码、表格等嵌套，token 归属与引用依赖 | `ryne-parser` 提供语义，`ryne-syntax` 提供只读查询 |
| Block 树 | 有序、不重叠源码片段及累计字节长度，块 ID 到锚点的目录 | `ryne-syntax` 提供结构，`ryne-session` 持有当前版本与焦点覆盖 |
| 块投影 | 块内源码与展示的映射、样式、隐藏范围、原子对象 | `ryne-projection`，功能层提供声明式贡献 |
| 布局单元与高度索引 | 块内字形、命中几何、估计/实测高度、累计高度 | `ryne-ui` |
| 资源与请求 | 代码高亮、语言识别、公式、图片和图表结果 | 既有扩展端口、会话调度和服务实现 |

不为每个字符建立块，也不为每个语义节点复制一份源码。块内容通过当前快照及范围读取。区块树可以共享未变分支，Block 树提供位置信息，二者通过身份和锚点关联。

### 1.1 四种粒度

- **语义块**表达 Markdown 结构，可嵌套，如引用包含列表，列表项包含段落和代码。
- **编辑目标**表达一次操作的对象，如段落、表格单元格、列表项或代码正文。单元格使用表格 ID 和稳定子身份，不能把可变行列号当唯一身份。
- **源码片段**负责字节分区，覆盖正文、标记、前缀、空行及未支持原文。所有片段拼接必须恰好等于源码。
- **布局单元**负责垂直流，可是完整短段落、代码物理行组、表格行或独立资源。一个语义块可有多个布局单元。

第一版不强求四者一一对应。容器范围覆盖子块是正常的，字节和高度的累计叶子必须各自互不重叠。

例如源码 `> - a\n>   b\n` 共 12 个 UTF-8 字节，引用、列表、列表项可以具有重叠的源码包络。底层一种合法分区是 `> `、`- `、`a\n`、`>   `、`b\n`，长度分别为 2、2、2、4、2，总和仍为 12。正文编辑目标通过映射跳过容器前缀；选择整个引用则使用完整包络。片段只是存储分区，不要求与解析器 token 一一对应。

若这个引用包含两个布局单元，高度分别为 `h1`、`h2`，容器独有间距为 `p`，累计高度为 `h1 + h2 + p`。引用背景覆盖这个范围，不再追加一个同样高度的“父块”。

### 1.2 身份与版本

`BlockId` 在一次文档会话内分配，与内容 hash、数组下标和绝对 offset 无关。普通块内修改保留 ID。拆分默认前半保留 ID，后半分配新 ID；合并保留前块 ID。明确的移动命令可以沿用被移动子树的 ID，普通粘贴相同文字不自动视为移动。

删除后旧 ID 不得分配给无关新块。撤销可恢复历史持有的同一逻辑 ID，或经位置映射重建身份，但第一版应固定一种策略并测试；建议保留有界历史身份记录。重新打开文件建立新的文档身份，旧缓存和任务不能跨文档接收。

全文重解析后的匹配优先使用事务证明未修改的区间，再校验边界与语义种类；重复内容不能只靠文本匹配。结构模糊的块可以分配新 ID，正确性优先于缓存命中率。

建议区分以下版本，而不是一个全局代次承担所有用途。

| 版本 | 变化条件 |
| --- | --- |
| `SnapshotId` | 已提交源码变化 |
| `content_revision` | 该块原始字节变化 |
| `semantic_revision` | 块结构、容器或外部引用依赖变化 |
| `projection_revision` | 显隐、模式、样式或对象投影变化 |
| `layout_epoch` | 字体、可用宽度、缩放、度量资源或布局规则变化 |
| `composition_generation` | IME 临时文本/选区变化 |
| `viewport_generation` | 用户滚动、跳转或视口尺寸变化 |
| `frame_generation` | 一次可供绘制与命中的几何发布 |

内部缓存可以跨源码版本复用，公开查询必须绑定当前源码和帧令牌。不得保存一串逐键位置映射供每次查询从头回放。

## 2. 源码位置树

### 2.1 结构与不变量

使用累计长度的平衡 B+ 树作为候选实现。叶页存放稳定片段句柄、角色、所属最内层编辑目标和 UTF-8 字节长度；内部页保存子树累计字节数。片段合并/拆分时维护句柄定位目录，不暴露可悬空的裸指针。

块目录通过起止锚点描述范围。锚点包含片段句柄、片段内偏移和边界亲和性。父容器保存自身完整源码包络以及子关系，不能再次作为字节叶子计入总长度。语义范围是否包含尾随换行沿用既有查询，分隔空行另有明确归属。

必须始终成立：

1. 根累计字节数等于对应源码长度，叶片段无缝覆盖 `[0, source.len())`。
2. 片段切分不拆 UTF-8 字符或 CRLF；光标和删除另检查 grapheme 边界。
3. 块锚点可解析，父子范围包含关系有效，共享起终点的顺序确定。
4. 空块、空单元格与 EOF 使用显式零长度锚点目录，零长度实体不参与按长度下降的歧义选择。
5. 原始源码、裸 CR 语义视图和局部解析输入的身份明确区分，对外范围绑定原始源码。

### 2.2 双向查询与成本

| 操作 | 方式 | 成本边界 |
| --- | --- | --- |
| `offset → 片段` | 从根按累计长度下降 | `O(log M)` 页访问 |
| `offset → 编辑目标/祖先` | 片段归属加语义祖先链；边界按亲和性与显式锚点选择 | `O(log M + D)`，另计局部查询 |
| `BlockId → [start,end)` | 由锚点找到叶页，累加路径左侧兄弟长度 | 两次 `O(log M)` |
| 长度变化 | 更新变动页和祖先累计值 | 单片段 `O(log M)`，不写后续块绝对 offset |
| 插入、删除、移动 | 更新受影响片段、句柄与块目录，维护树平衡 | 随处理片段数增长，不能统一称为 `O(log M)` |

`M` 为片段数，`D` 为容器深度。具体页容量和实现选型由基准决定，不把树算法成本等同于完整输入事务成本。若直接用一个全量复制的 HashMap 保存每版句柄目录，会抵消路径复制收益；需要分块共享目录或会话内版本受控的更新。

### 2.3 焦点覆盖与失焦归并

焦点覆盖是基础索引上的一个连续替换区间，不是未提交源码。进入块时记录基础索引和基准区间 `[s,e)`；每次确认输入立即提交新源码并更新覆盖内的片段及锚点。

设活动区间当前长度为 `L`，`delta = L - (e - s)`，使用带检查的有符号运算。当前查询规则为：

```text
当前位置 p < s        → 基础索引 p
s ≤ p < s + L         → 活动覆盖 p - s
当前位置 p ≥ s + L    → 基础索引 p - delta
```

端点按照亲和性和零长度锚点处理，不能仅套用不等式。反向查询对后续锚点加 `delta`，活动锚点查新局部映射，跨过覆盖的父容器分别求起止位置。等长替换虽然 `delta = 0`，内容版本、局部锚点和语义仍需更新。

例如 A 为 `[100,120)`、B 起于 `120`，A 增加 6 字节后立即查询为 A `[100,126)`、B 起于 `126`。A 缩短 5 字节则 B 起于 `115`。不允许查询暂时返回旧的 B 起点。

失焦归并只写回活动片段与累计值，归并前后同一源码版本的查询结果完全一致，不增加历史或 dirty。点击另一块先用当前帧获得源码锚点，再归并。保存读取已提交源码，不等待归并。

片段内位置也有版本。删除或替换片段时，必须先按事务映射迁移仍存活的光标、显隐、滚动及任务锚点，再移除旧句柄。被删除的锚点按亲和性落到替换边界；不得用新片段同名句柄解释旧偏移。历史保留所需的旧锚点记录，历史淘汰后才允许释放对应记录。

以下情况提前归并并走一般事务：跨块替换、多区间命令、块边界或容器变化、Undo/Redo、切换文档，以及覆盖超过配置预算。源码模式仍可按连续编辑范围使用覆盖；无法证明时直接更新树。一个焦点会话只保留一个基准索引与一个当前覆盖，不能按键累积版本链。

基础树逐键更新同样只需更新路径。先实现这一正确基线，再测量焦点覆盖是否降低分配或维护成本；不要为了延期维护而延期内容提交。

## 3. 源码事务与局部语义

### 3.1 发布流程

1. 输入携带源码身份和 UTF-8 范围。结构视图由当前实测几何映射；平台输入先从 UTF-16 转换，保留现有 grapheme 和 CRLF 校验。
2. `PreparedEdit` 在旧快照上解释所有 edit，生成候选源码、逆事务和 `PositionMap`。多 edit 不能逐个用新坐标解释旧范围。
3. 定位受影响块、父容器和边界，准备局部或全文语义候选，同时准备位置树、依赖变化和选区。
4. 通过已有结构检查、验证器和历史策略后，一次发布源码、语义、位置查询状态与选择。失败保留原状态；不得先发布源码再让旧 AST 接受结构命令。
5. 使相关投影与布局失效，按当前工作集生成可用的新帧。新帧未就绪时不得沿用旧像素执行编辑。

行内补全可以复用完全相同候选快照的解析结果，需要将该候选与 PreparedEdit 一起传递并核对身份、方言和配置。文本相同但重新分配的 `SnapshotId` 不能直接冒充同一候选。

### 3.2 局部放行与回退

局部处理返回 `Local(delta)` 或 `FullRequired(reason)`，不是尽量解析一段后默认接受。必须证明左右边界、容器上下文和区外依赖可复用。检查修改后的整片受影响物理行，删除也可能把两段字符拼成新标记。

| 场景 | 初期策略 |
| --- | --- |
| 已确认闭合围栏的字面正文编辑 | 检查围栏字符/长度、闭合位置、容器前缀、缩进和换行；确认未引入新闭合行才局部更新 |
| 安全顶层段落 | 重解析完整段落及必要边界上下文，确认未转成其他块；依赖外部引用时需要等价解析上下文 |
| 列表、引用内正文 | 初期扩大到完整最外层受影响容器；校验续行、缩进、列表松紧和相邻块 |
| Setext、表格分隔行、空行修改 | 合并相关前后块，直到能证明后缀状态收敛 |
| 围栏变化、跨块粘贴/删除、结构命令 | 初期全文路径，逐类通过差分后再开放局部 |
| 新增/删除/改动引用定义、重复定义顺序 | 初期全文路径，包括之前未解析成功的引用使用点 |
| 未支持结构或边界状态未知 | 全文解析，保留可编辑原文 |

局部预算同时限制字节、节点和向外扩展次数，数值由基准确定。预算达到后完整回退并记录真实处理量。截断输入的 EOF 会自动结束部分语法，不能把这一结果当作原文后缀独立的证明。

### 3.3 解析器与查询接口迁移

现有快照拥有单个 Source、全局节点编号和 token。不能将局部快照的裸节点编号直接拼入主快照。拟议语义片段使用片段内节点 ID 与相对范围，公共节点引用包含片段身份；片段关联当前源码的范围由位置树解析。

先把直接访问全局节点数组的热路径收敛到 `SemanticQuery`，再提供共享分支的语义视图。需覆盖节点父子关系、lossless token、字段来源、引用定义及已解析/未解析依赖、物理行和结构索引。仅迁移 AST 而漏掉 token ownership 不算完成。

源码片段仍可以借用当前完整 Source 的范围，第一版无需先替换存储。全文解析后端继续作为差分基线和运行期回退；测试中的双算不能成为正式按键路径。

## 4. 分块投影与内容验证

### 4.1 投影

块投影保存相对源码范围、展示文本、样式区间和双向映射，覆盖隐藏标记、空单元格、引用尾行、公式与资源原子对象。顶层目录累计源码/展示长度并支持范围查询，普通输入不 flatten 全文字符串。

如果两个展示片段在语义上连续，grapheme 分段必须连续处理。隐藏 span 的边界不一定是 Unicode 边界，不能使用固定 64 或 256 字节重叠来保证正确性。先选择有显式安全分隔的投影边界，无法证明时合并处理。UTF-16 检查点也要在内容变化时局部更新并绑定当前版本。

过渡阶段允许全文投影加块布局，但应标明仍有线性投影成本。未知扩展未声明范围和依赖时走既有完整路径；不能假设其只依赖当前块。

### 4.2 内容指纹

块可缓存原始 Markdown 字节长度、`CRC-64/ECMA-182` 和对应内容版本。固定算法参数和检查向量，不能仅写“CRC64”而由实现自由选择变体。需要对可信外部摘要核对时可以另用 SHA-256，本阶段不引入持久化摘要协议。

- 事务证明片段未修改时，沿用指纹，无需重新扫描屏外块。
- 修改后标记指纹待计算，需要比对或空闲/失焦后再计算；超长块采用有界调度。
- 长度和指纹相同只筛选候选，随后比对原始字节和依赖。测试必须能注入相同指纹、不同字节。
- 内容相同不代表 `BlockId` 相同，也不代表引用解析、显隐、字体或排版相同。
- 父容器的连续字节摘要与按顺序组合子摘要的树摘要使用不同类型。树摘要需编码节点种类、长度和边界，不能简单 XOR 或无分隔拼接，也不能冒充原始字节 CRC。

缓存复用依次验证内容、语义依赖、投影依赖和布局参数。全局偏移变化本身不要求重算块内字形，但必须重新绑定当前帧位置。

## 5. 布局单元与高度目录

### 5.1 高度的唯一归属

构建有序布局流，使用可更新的累计高度树。初期可用平坦目录加 Fenwick 树，在结构改动时重建目录；后续若需要局部插删，再采用分块平衡树。这个过渡版本的重建成本必须统计，不能宣称全部局部化。

每个单元记录 `UnitId`、所属块/子身份、源码锚点、估计摘要、当前高度、度量状态和布局键。高度有限且非负，正文空行保留可命中高度；纯逻辑零高锚点走独立目录。

列表或引用只累计内部可见流单元，加容器自身独有的间距。代码标题栏/内边距各只算一次。表格每行高度等于该行各单元格实测高度最大值加既有内边距。相邻块间距明确归属边界单元，避免两侧重复计算。

外层引用背景按范围绘制可见交集，左上入口和 `quoter` 仍属于原始起始位置，不因进入视口而复制。列表编号所需的同级信息来自语义目录，不能仅靠已挂载行计数。

### 5.2 廉价估计

打开后用解析/投影已有摘要或一次线性扫描建立估计，不执行每块文字精排。用不同宽度近似估计 CJK、普通正文和等宽代码，不逐字调用字体系统。宽度取内容栏减缩进及控件预留，保持既有极窄窗口规则。

示意公式只用于预算和定位，不用于编辑命中：

```text
近似视觉行数 = Σ max(1, ceil(当前逻辑行的近似字宽总和 / 有效内容宽度))
估计高度 = 近似视觉行数 × 主题行高 + 单元独有的间距
```

换行和软换行必须按当前展示语义计算。第一阶段可直接使用已构建投影的行摘要；后续按块生成摘要。长单行只保存必要长度/宽度统计，不为估计创建字形数组。

| 内容 | 估计来源与精排粒度 |
| --- | --- |
| 段落、标题 | 文字类别摘要、行高、宽度；首版整段精排 |
| 列表、引用 | 内部内容摘要加容器缩进与独有间距，容器本身不重复求和 |
| 代码 | 正文物理行数和行长度摘要，按行组精排；折行长单行单独记录 |
| 表格 | 行数和单元格长度摘要，沿用当前等宽列和最小列宽；整行全部单元格一起精排 |
| 图片、Mermaid | 已缓存自然尺寸按宽度缩放，未知时采用有上限的占位或代码高度估计 |
| 行内公式 | 已缓存度量优先，未知时用近似对象宽高；可见行完成公式度量后才作为实测几何发布 |

`Estimated → Measured` 表示当前布局键下度量已完成。参数变化后旧实测值可以作为新的估计，但不得作为当前命中几何。回收字形后可保留高度和锚点摘要；再次命中前重建几何。主题若只改变颜色可以复用尺寸，现阶段需先区分颜色与度量依赖。

## 6. 视口调度与资源

### 6.1 工作集

精排集合包括视口、预取区以及当前光标、IME 和导航/命中目标。预取初始可设上下各一屏，随预算和测量调整，快速滚动优先滚动方向。远处光标可形成独立的小工作集，不要求从视口到光标之间全部精排。

每帧先满足交互目标和实际可见区，再补预取。高度变更可能改变“哪些单元可见”，因此更新后重新查询覆盖区，限次处理并在下一帧继续。不得在同一帧无限循环直到全部估计收敛。预算不足时允许短暂占位且不可编辑命中，记录缺口持续时间；不能把永久占位当作结构呈现完成。

GPUI 排版与资源上传保持当前线程约束。帧预算只是调度预算，不能强制抢占一个同步 shaping 或高亮调用。单个巨大段落/代码行的长耗时必须单列，并保留安全完整排版路径。

### 6.1.1 屏外焦点与交互保留（2026-11-15 补充，待实现）

参考 VeloType 的[屏外焦点行保留](https://github.com/manyougz/velotype/blob/07a24a9b5b953539dede8e61a1f7d9d0adbba590/src/editor/window_state.rs#L68)：远处焦点单独保留，不把焦点到视口之间的所有行加入工作集。Ryne 当前由正文编辑器的 `FocusHandle` 和输入桥接持有焦点（`crates/ryne-ui/src/element.rs`、`input.rs`），不是每块一个输入实体，因此采用以下适配，不为虚拟化改成多份编辑状态。

- 正文输入宿主在窗口文档存活期间保持挂载；只有正文布局单元按视口回收。不把焦点移到窗口根节点，避免破坏标题栏原生操作。
- 布局工作集是可见区、预取区与交互保留单元的去重并集。保留当前选区活动端所在单元、IME 临时替换及候选定位所需单元、尚未完成的导航/命中目标；选区中间部分不因跨屏选择而全部精排。
- 保留粒度沿用安全布局单元：短段整段、代码行组、表格整行及全部单元格；引用/列表只保留必要正文与祖先缩进/装饰元数据，不挂载整个外层容器。超长单段和长单行仍走已声明的慢路径，不能谎称一个光标只需一个视觉行。
- 每个单元只有一个布局身份、一个高度贡献和一份当前几何。屏外保留单元回到可见区时合并工作集，不创建第二份正文、IME 输入处理器、背景或高度。绘制和指针区域仍裁剪到视口，不在屏幕边缘画一个替身光标。
- 这类保留称为“交互保留”，与阶段 D 的“焦点覆盖”（源码位置索引优化）无关，不等待 D 才实施。

拟议 `InteractionRetention` 由 UI 持有文档身份、源码锚点/亲和性、保留原因、当前投影与预编辑代次；具体名字可调整。源码事务后先映射锚点，再从当前目录解析布局单元。不能把旧行号、旧像素或失效 BlockId 当作新目标；原块删除后根据已提交选区重新定位，不能按相同文字寻找替身。布局发布与保留集合切换必须原子可见。

| 事件 | 焦点、滚动及保留行为 |
| --- | --- |
| 滚轮/触控板、滚动条或只读章节/脚注跳转 | 保持正文焦点与源码选区；仅因光标屏外不设置 `ensure_caret`，允许继续阅读远处内容 |
| 确认输入、方向键、显式“回到光标” | 先准备当前目标的真实几何，再沿现有规则使光标可见；不使用旧高度强行回滚 |
| IME 预编辑更新 | 保留输入宿主和当前临时范围；必要时使候选锚点可见，非必要显隐与资源重排延后 |
| 平台查询屏外候选几何 | 活动输入范围必须预先准备匹配当前临时版本的实测位置；几何暂缺时尝试当前安全布局路径，不能以 `None` 加异步重试作为正常候选定位策略，也不能伪造视口边缘矩形；平台行为须真机验证 |
| 点击新正文位置 | 先完成新目标精排/命中并按现有 IME 确认策略切换，再释放旧保留；不能先卸载旧输入上下文 |
| 主题/缩放/窗口宽度变化 | 保留逻辑锚点与焦点，旧度量立即失效，重新精排保留单元后发布几何 |
| 窗口失焦/重新聚焦 | 沿用既有光标闪烁及平台组合输入生命周期；不把屏外裁剪当成真实失焦，不额外提交/取消预编辑 |
| 文档替换/关闭、导航完成或被新请求取代 | 沿既有保存/IME 流程处理，清理旧文档保留及临时导航请求；旧任务不得恢复它们 |

正常情况下只有一个活动编辑上下文；导航/命中请求采用最新请求替换尚未开始的旧请求，不累积跳转历史的所有布局单元。多单元预编辑保留其真实依赖，不能硬裁成一个块。预算紧张先回收预取和非必需缓存；必需几何无法在快路径完成时走同版本安全慢路径，记录原因与耗时，不能丢焦点或取消用户输入。交互保留不自动触发该容器内全部图片/图表任务。

2026-11-15 可行性复核：`paint.rs::paint_frame` 当前每帧调用 `window.handle_input`，仅保留 `FocusHandle` 不足以保证平台输入桥接存活。B3 必须让正文宿主每帧完成输入注册，即使可见区只有占位或没有文字，不能把注册放进“当前有可见行”的条件中。当前 `input.rs::bounds_for_range` 的 `None` 在 GPUI 0.2.2/macOS 会转为屏幕原点零矩形，Windows 则跳过候选定位更新；因此它只能作为异常拒绝，不能成为正常虚拟化策略。活动临时范围的实测几何须在输入状态发布/下一次平台查询前准备，纯滚动只重绑定当前坐标。平台是否接受真实屏外候选位置仍待真机验证；若不可靠，首版在预编辑期间约束滚动使候选锚点仍在视口内，且明确记录这一限制，不强行承诺预编辑下任意远滚。

此阶段保留完整只读投影，几何的局部化仍需 B2/B3 统一迁移：`layout_frame.rs` 的行查询、`input.rs` 的命中、表格整行高度、上下导航和 PDF 使用边界不能仅在绘制函数外加一层过滤。保留焦点的 UI 生命周期与按需排版是两个验收项，前者不能证明后者完成。静态证据与修正见[可行性补充](FEASIBILITY.md#6-2026-11-15-屏外焦点与脚注联动复核)。

脚注往返共享这个协议：目标未精排时先定位并测量，阅读跳转保留原光标；返回栈仅保存锚点，不保留每个历史目标的字形。语义与交互细节见[脚注规划](../../49_Footnotes_Design_And_Plan.md)。

### 6.2 资源的三类集合

1. **资格目录**记录按既有规则允许预览的候选和身份，跨视口保持。当前最多 32 个正候选及提供者规则继续有效。
2. **请求集合**由资格目录与视口/预取工作集求交，再按光标、模式、冻结和资源状态决定是否请求。
3. **存活与淘汰集合**按文档内容、资源键和缓存预算维护。滚出视口不等同删除；旧文档或内容已替换的结果不得重新挂载。

资格目录尽量保存范围、种类和轻量身份。昂贵的正文复制、Data URL 解码和请求参数构造在进入请求集合后进行；若兼容旧接口仍先构建全部 `PreviewInput`，必须单列这项前置成本，不能只统计最终启动的任务数。

资源键至少包括服务/提供者实例、内容、配置代次和渲染参数。任务还携带文档身份和请求代次。完成时先校验内容和服务身份，允许仍有效的屏外结果进入有界缓存；是否挂载再检查当前模式、冻结状态和帧版本。一次无关的前方编辑不必废弃内容相同的资源，但不能通过放宽检查接收已改变内容的结果。

首帧可以使用普通代码颜色，再按预算识别和高亮。高亮的词法状态可能依赖整个代码块，首版对进入工作集且符合现有大小限制的块整块请求，文字几何仍按行组。颜色变化复用尺寸，字体/字重或其他度量变化必须失效。语言识别预算与实际高亮预算分开。

图片和 Mermaid 沿用已有下载、解码、像素、缓存、时限和失败终态规则。失败不因滚动而无限重试。公式资源也应在投影准备前支持惰性请求；仅延迟 SVG 绘制不能节省此前度量成本。PDF 导出使用独立冻结快照和既有导出服务，不受屏幕视口限制。

### 6.3 缓存依赖与失效

| 变化 | 至少失效的范围 |
| --- | --- |
| 段落正文、行内标记显隐 | 当前投影/布局及相邻间距 |
| 前方块仅增长且后续上下文不变 | 前方相关块，高度前缀更新；后续块内字形可复用 |
| 列表移动、缩进、编号位数或松紧变化 | 受影响子树、同级编号宽度、父容器与边界 |
| 表格单元格文字 | 当前单元格和行高；首版可重排整行，其他行复用 |
| 表格列数、列对齐、列宽规则 | 全表布局键变化，按视口重建 |
| 引用定义 | 所有相关使用点；依赖不完整则全文语义回退 |
| 宽度、字体、缩放 | 所有布局键失效，屏外仅估计，可见优先 |
| 控件 enabled/hover | 更新动作/绘制状态；只有占位尺寸改变才重排文字 |
| 模式、公式字体、资源度量 | 相关投影/布局；切换全文源码模式重建流目录 |

未知贡献者保留完整安全路径。不能删掉现有控件代次校验来获得表面命中率，需要把文字布局依赖与动作身份分别发布。

## 7. 高度修正与滚动锚点

### 7.1 批量发布算法

1. 从最新已精排画面选择锚点，通常为视口顶部附近的可见文字位置。记录源码位置、亲和性、视觉行内位置与屏幕 Y。没有文字时使用资源块起点及局部偏移。
2. 编辑后先用 `PositionMap` 迁移锚点。锚点被删除时按明确的前后亲和性选择邻近仍存在位置。
3. 收集本批次有效实测结果，更新高度索引。若锚点所在块重排，用新几何重新求该位置的块内 Y。
4. 应用以下关系，并与几何同帧发布。将坐标统一到内容区，工具栏/侧栏等窗口偏移单独转换。

```text
anchor_document_y_new = 新单元起点Y + 锚点的新块内Y
scroll_y_new = anchor_document_y_new - anchor_screen_y_old
scroll_y_new = clamp(scroll_y_new, 0, max(0, total_height_new - viewport_height))
```

5. 重新查询视口覆盖集合，补排缺口。一个批次只进行一次对外滚动补偿，避免逐资源结果反复抖动。

锚点上方增高 60 px、锚点块内位置不变时，滚动量增加 60 px。若锚点本身因折行下移 30 px，还需计入这 30 px。不能只累计前方块的高度差。

### 7.2 用户意图优先

滚轮、拖动滚动条、大纲跳转和“确保光标可见”产生新的意图代次。提交高度结果时在最新意图上重新捕获或解析锚点，不能让后台保存的旧 scroll 值覆盖用户操作。

远距离源码跳转先定位目标块并精排目标，再按目标行对齐；不必精排之前全部块。按滚动条比例跳转先由估计总高确定目标，拖动期间以最新比例为意图，释放后建立文字锚点。总高变化会改变滚动条滑块，这一点不能承诺完全不动。

文末钳制可能导致无法保持原屏幕 Y。已有明确“保持文末”意图时可使用文末锚点，普通阅读不自动切换为跟随文末。插入/删除锚点、图片内部尺寸变化、全局字体调整也可能产生合理视觉变化，验收需分类。

累计高度和滚动使用 f64，只在进入 GPUI 绘制时转换视口附近的相对坐标。禁止先把巨大绝对 Y 转为 f32 再相减。

### 7.3 命中、选区与 IME

点击未知区域先精排目标，再以原事件位置和当前版本重新命中。需要延期时保留原始事件及令牌，若文档、预编辑或视口已改变则重定位或取消该旧事件，不用旧像素解释新源码。

跨屏选区保存完整源码范围。复制、替换、删除由源码执行，不依赖挂载单元；选区绘制只生成可见片段。上下导航在相邻目标尚未精排时请求目标几何，拖选自动滚动持续补排边缘。

IME 预编辑有独立临时覆盖，不写入已提交源码、历史或保存。候选框使用当前临时版本的实测几何，不能返回估计矩形。确认候选一次提交，确认 Enter 不重复执行结构命令。预编辑和拖选期间延后非必要显隐与资源重排；正文变化所必需的几何仍需更新。

两种覆盖按固定顺序组合：基础索引加焦点覆盖得到已提交版本，再应用 IME 临时替换得到显示版本。平台 UTF-16 范围查询针对临时文本，确认时先转换回已提交事务范围。不能把 IME 的长度差再次加入已包含预编辑的几何，或在取消时回退已提交焦点编辑。

## 8. 保存、回退与复杂度边界

保存冻结当前已提交 Source，不依赖焦点覆盖是否已归并，不从区块树序列化。沿用 IME 确认、串行保存、快照回执及同目录临时文件与重命名，未改字节和原始换行不变。保存旧快照成功不能清除新编辑的 dirty。

回退分层：局部语义无法证明时全文解析；投影验证失败使用匹配当前源码/预编辑的可编辑源码回退；几何未准备好时延迟命中并生成当前布局。故障回退不改变原始字节，不将普通文本模式当作大文件正常功能替代。

最终复杂度需分别报告：源码复制、语义处理字节、投影重建字节、平台索引更新、验证器、布局单元和资源工作量。当前 `Source::apply` 的整串复制仍为线性成本，全文落盘仍与文件大小相关。只有这些成本均有测量，才可判断是否值得后续引入分段源码存储。
