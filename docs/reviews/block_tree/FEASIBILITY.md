## 3. 关键设计修正

### 3.1 分开语义、字节和高度

列表、引用的父节点范围覆盖子节点。若将父范围长度与子范围长度同时求和，全文 offset 会错误；同样不能将容器总高度和内部行高度重复累计。底层使用互不重叠的片段或布局单元，容器只引用其边界并贡献自身独有的间距和装饰。

表格同一行的单元格并排，高度取最大值，不是累加。当前实现等宽列，首版保持这一规则。将来采用按内容自适应列宽时，才需要另行设计全表摘要和列宽收敛。

### 3.2 “失焦归并”不是内容提交点

源码、选择和当前位置查询在每次确认输入后立即更新。失焦只把覆盖合入基础索引。B+ 树本来只需修改叶页和祖先累计值，逐键更新也无需遍历后续块，因此覆盖带来的性能收益必须与直接更新比较，不能默认更快。

焦点覆盖只支持一个连续活动区间。结构修改、多区间事务和历史恢复可先归并，再执行完整事务。不引入多层无界覆盖，IME 另有临时层和代次。

### 3.3 局部解析最难的是证明范围独立

即使只改一个字符，也可能形成围栏闭合、Setext 标题、列表或表格。正文还可能依赖屏外引用定义。相同字节不等于相同语义；同一父容器内列表松紧属性变化也可能影响其他条目。

当前仓库内解析器允许后续修改，但现有接口没有完整的增量上下文和快照拼接能力。应先在解析/语法层验证最小快路径，再收敛业务层查询接口。没有证据时保留全文路径，不能直接拼接不同 `Source` 身份的节点数组。

### 3.4 资源请求不能只过滤最终绘制

当前预览缓存用输入集合判断哪些缓存仍属于文档。直接把输入替换为视口子集会让屏外缓存被删，滚回时重复加载。应把完整的有界资格目录、当前请求集合和缓存淘汰分别传递。

第一版保留现有文档内最多 32 个预览候选的资格策略，按原有源码顺序和提供者规则确定资格，再在其中按视口调度。第 33 个候选不会因为滚入视口自动突破资格限制。改为“最多 32 个驻留、任意候选可轮换”会改变行为和总工作量，留待单独评估。

### 3.5 版本正确性与跨版本复用同时成立

`SnapshotId` 必须参与对外查询和发布校验，但若直接将它作为所有块布局的唯一复用键，任意编辑都会使全部块缓存失效。内部缓存按块内容和依赖复用，对外组装新的帧令牌，重新绑定当前源码位置。旧帧始终不能处理新版本事件。

## 4. 风险与处置

| 风险 | 后果 | 处置与验证 |
| --- | --- | --- |
| 估计严重偏差 | 滚动条变化、远跳落点错误 | 只承诺锚点补偿；分批测量并重新查询覆盖区，记录未覆盖时间 |
| 一个块巨大 | 屏内一次精排仍长时间阻塞 | 代码行组、表格行先拆；长段和长单行保留显式慢路径 |
| 全局无效化遗漏 | 列表编号、宽度或引用结果沿用旧值 | 明确依赖矩阵，未知提供者使用现有完整路径 |
| 焦点、IME、资源三类变化叠加 | 命中和候选框漂移 | 组合版本令牌；预编辑/拖选期间延后非必要资源重排 |
| 隐藏标记或 grapheme 边界错误 | 选区、删除破坏源码 | 全量映射差分，跨隐藏 span 连续分段，不用固定重叠长度 |
| CRC 相同即复用 | 碰撞造成错误结果 | 强制碰撞测试，字节和上下文验证，ID 与指纹分离 |
| 新旧快照及缓存叠加 | 峰值内存上升 | 分项预算、有限任务与快照持有、视口优先淘汰 |
| 仍有全文工作却宣称局部性能 | 无法满足大文档输入目标 | 分阶段计时、字节/节点计数；如实记录全文回退与异常样本 |

屏外焦点按一个活动编辑上下文和当前 IME 必需单元保留，导航请求只保留最新目标；短块压力下精排工作量不能随两者间距离增长。对多单元组合输入、超长段落、整行超高表格，依赖工作集本身仍可能很大，保留正确慢路径并单列测量，不设会截断用户输入的硬单元数上限。

脚注首版需要新增解析配置贯通、容器前缀、编号原子映射/基线混排、只读导航请求与跟踪锚点，不是添加一个目录就能完成。完整证据、已运行的 22 例锁定后端探针和未验证项见[脚注可行性报告](../footnotes/README.md)。该探针不验证 Ryne 新节点、GUI、IME 或 B3 性能，FN0 仍未整体放行。
