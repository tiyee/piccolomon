## 核心约定

| 项目 | 本方案约定 |
| --- | --- |
| 数据真相 | 源码是唯一可编辑数据；语义、映射、投影和布局都是派生数据 |
| 两棵树 | 区块树表达语义嵌套；Block 树按源码顺序累计不重叠片段的字节长度 |
| 高度索引 | 独立于字节索引，累计不重叠布局单元的高度；父容器不重复累计子块高度 |
| 内容修改 | 每次确认输入立即提交源码和一致的查询状态；失焦只归并索引，不延迟内容保存 |
| 局部处理 | 有边界和依赖证明时局部更新；不能证明时扩大范围或全文解析 |
| 视口处理 | 全文保留语义与轻量目录，实际视口、预取区及必要交互目标按需精排 |
| 屏外焦点 | 正文输入宿主持续挂载；保留活动编辑与 IME 必需单元，和可见区去重，不精排两者之间的全部内容；阅读滚动不强制回到光标 |
| 高度修正 | 同一批高度更新和滚动补偿一起发布，尽量保持源码锚点的屏幕位置 |
| 内容指纹 | CRC64 用于筛选复用候选；一致性仍依赖字节、事务证明和上下文 |
| 保存与历史 | 保存已提交源码快照，保留未修改字节和 LF / CRLF / CR；沿用撤销、重做、验证和保存回执 |
| 身份检查 | 命中使用当前帧；后台结果验证文档、内容和配置身份；IME 另带临时代次 |

## 推荐实施路径

1. 固定测量基线，建立块目录与失效规则。先保留全文解析和投影。
2. 引入廉价高度估计、块内布局缓存和累计高度索引，按视口精排并修正滚动锚点。
3. 将代码高亮、语言识别、图片、公式和 Mermaid 的昂贵工作接入范围调度，保留现有限额及故障回退。
4. 完善累计字节树与焦点覆盖，验证归并前后映射一致。先允许每次输入更新树路径，焦点覆盖作为可比较的优化。
5. 验证局部语义后端，再迁移分块投影和 IME 临时覆盖，消除普通编辑的全文派生成本。

步骤 2 不依赖步骤 5。它能够先降低全篇文字精排的成本，但首次全文解析、全文投影、源码复制以及超长单块仍需单列测量。步骤 3 的公式等资源惰性化需要调整投影接口，不能仅在绘制层隐藏对象。

## 预期收益与边界

| 方面 | 预期改善 | 保留的成本或风险 |
| --- | --- | --- |
| 首屏与重新排版 | 只精排可见工作集，减少字形和几何分配 | 打开仍全文解析并建立目录；估算也有线性初始化成本 |
| 普通输入 | 最终只重建受影响语义、投影和布局 | 过渡阶段仍全文解析/投影；当前 `Source::apply` 复制整串源码 |
| 滚动 | 复用已精排块，按需补齐新区域 | 远跳时估计可能不准，单个超长段落可能阻塞 |
| 映射维护 | 前方编辑无需逐个改写后续块的绝对 offset | 结构变化仍需处理受影响子树，ID 与边界归属需严格定义 |
| 资源 | 屏外块不再无条件发起昂贵计算 | 缓存生命周期、32 个预览资格上限和高亮预算必须单独处理 |
| 保存 | 继续直接保存同一份源码，无需树序列化 | 全量落盘仍与文件大小相关，性能优化不改变保存语义 |

这里的“普通输入通常只更新当前块”是分阶段验收目标，不是现状或所有 Markdown 编辑的保证。具体通过条件见 [实施与验收](IMPLEMENTATION.md)。

## 早期原型

本目录的 `Cargo.toml`、`src/` 和测试属于历史上的“直接编辑树，保存时生成 Markdown”实验。它与当前源码驱动方案具有不同的数据所有权，现有测试不证明局部解析、累计长度树或视口排版可用。保留原文件便于追溯，运行说明见 [历史原型说明](PROTOTYPE.md)。
