## 当前实现

### 块目录

`ryne-syntax::directory::BlockDirectory` 持有当前只读 Source，提供快照校验后的 ID、范围、父节点和双亲和性查询。包含段落、标题、引用、列表/条目、代码、表格/行/单元格及原文块。裸 CR 使用既有同字节长度语义视图，公开身份仍是原始 Source。

语义包络允许嵌套，不作为长度求和的叶子；`SourcePiece` 是不重叠的原始字节分区，覆盖标记、容器前缀、空行及未支持源码，分区不拆 UTF-8 或 CRLF。它仍是平坦分区，**不是阶段 D 的可增量 B+ 树**。

身份规则：

- 事务证明未改的区间优先匹配；重复字节不会自动被视为同一块。
- 普通内部编辑和有正文存留的首字符修改保留 ID；同类型拆分前块保留，合并保留前块。
- 起点插入重复段落时，先为原段落保留 ID，再给新段落分配 ID。
- 整块替换、删除后粘贴、显式移动中被替换的范围，以及无法证明容器关系的情况分配新 ID。
- Undo/Redo 使用同一事务映射重建身份；已被删除的 ID 不复活，恢复的块获得新 ID。尚未加入历史身份保留表。
- `content_revision` 对不能证明原始范围未改的保留块递增；`semantic_revision` 保守使用当前源码修订，不声称引用依赖已经局部化。
- 目录先准备，再与源码和语义一起发布。验证失败不发布目录；选择、模式、临时 IME 和保存不建立独立可编辑树。

构建仍为全文目录重建，使用排序、树映射和范围索引；它增加派生成本，不能用于宣称输入已经达到局部复杂度。初始测量发现该成本不可忽略，因此会话首次查询时才建立目录；建立后随事务原子更新，未使用目录的既有编辑路径不承担额外构建成本。它仍可随时从当前快照重建，不维护逐键映射链。

### 局部精排缓存

文字缓存以现有完整逻辑行/单元格换行段为安全边界，不切断 Unicode 或公式上下文；超长单行继续走完整精排。保留相对展示起点、字形、折行和公式混排结果；每个新帧重新绑定绝对展示位置、源码映射、Y、表格行高和容器装饰。

键包括实际文字、完整 TextRun（字体、颜色、强调及装饰）、字号/行高、宽度、相对公式范围和不可变公式资源身份。缩放或文档切换清空缓存。CRC-64/ECMA-182 仅选择候选桶，随后精确比较文字与依赖；检查向量 `123456789 = 6C40DF5F0B497347`，并有强制碰撞测试。跨源码版本可以复用字形，旧事件几何不能借此变为有效。

每窗口最多 2048 项，以 16 MiB 保守估算 charge 限制保留内容；FIFO 淘汰，超大单行不进入缓存。这不是 RSS 硬上限，也不包含当前完整帧、GPUI 自身缓存和语义快照。大量互异单元超过预算可能抖动；视口工作集淘汰属于 B3。

本阶段仍全文遍历展示文本、计算候选摘要并组装几何，首次排版仍全文精排。**尚未交付视口精排、f64 滚动、高度估计、局部解析或屏外资源惰性化。**

### 控件依赖

文字 LayoutKey 使用预留宽度与前置控件定位目录，移除无关的动作代次。帧另持有当前控件代次；批次变化立即使旧控件动作失效，下一帧使用当前动作和可复用文字。文字几何与动作令牌分别校验，取消 IME 后恢复同一展示和尺寸时，正文仍可命中；动作继续要求当前控件代次。前置控件的索引/焦点范围或预留宽度改变仍使布局失效，避免复用旧索引。

## 验证与测量入口

```sh
python3 scripts/check-architecture.py
cargo fmt --check
cargo test --locked
/usr/local/opt/rust/bin/cargo-clippy clippy --locked --all-targets -- -D warnings
RYNE_SMOKE_BLOCK_TREE_ONLY=1 cargo run --locked -- --smoke-test
cargo run --locked -- --smoke-test
cargo run --locked -- --smoke-test-failure
cargo run --release --locked -p ryne-syntax --example block-directory
```

`RYNE_PROFILE=1` 增加 `source_apply`、`semantic_parse`、`block_directory_build`、`candidate_validation`、`preview_candidates`、`projection_build` 及 `shape_work`。既有 refresh、layout、paint 计时仍保留。`shape_work` 区分缓存命中、实际精排调用及处理的展示字节；不能把只绘制视口解释为仅排版视口。

计时是嵌套阶段，不应直接相加；`source_apply` 包含校验、复制及逆事务准备，`projection_build` 包含资源/样式与展示索引。解析记录按每次真实调用产生，可发现补全等路径的候选重复解析，但尚无跨调用关联 ID。

真实窗口新增 100 个不同段落及引用/列表/代码/表格/公式样例：前方插入后验证至少 100 次局部缓存命中且仅 1 次精排缺失；比较缓存和完整后端的字形、折行、公式度量及几何；验证动作状态变化复用整份 TextLayout、旧动作帧失效，并验证撤销。差分双算只在冒烟路径运行。

Windows 真机和人工输入法验收不由本机冒烟替代。

## 实际验证结果

- 架构检查、`cargo fmt --check`、`git diff --check` 通过；10 个私有包的依赖方向不变。
- `cargo test --locked` 首轮通过；后续改动后的最终 `cargo test --locked -- --test-threads=1` 为 444 通过、0 失败、2 个原有忽略。
- 中间一次并行定向重跑中，未修改的 `recovery::tests::live_slots_are_isolated_and_retired_writers_cannot_recreate_a_copy` 在释放草稿锁后立即读取处失败；最终串行全套通过。本次不修改草稿锁模块，也不声称已修复该偶发问题。
- 当前 Homebrew 配套 Clippy 的 `--locked --all-targets -- -D warnings` 通过。
- 新增专项真实窗口检查通过；完整真实窗口冒烟最终通过 0–395 阶段，包括新增差分与原有 IME、源码映射、格式、表格、列表、图片、公式、Mermaid、侧栏和主题检查。
- 完整冒烟曾发现取消 IME 后正文点击被动作代次误拒绝，已拆分文字/动作校验并重跑完整流程通过。
- `--smoke-test-failure` 按预期报告 stage 0 检查失败并退出码 1，没有让检查 panic 穿过原生事件循环。
- 原有两份 core 修改与开工备份逐字节一致；未触碰原有未跟踪文档和主题图标。未提交或发布。

这些结果只放行 A1/A2/B1 首批接入。B2/B3 及 C–F 的功能和性能验收仍未完成。

真实窗口专项样例中，前方插入后记录 `shape_work: hits=210, misses=1, shaped_bytes=30`，撤销记录 `hits=211, misses=0`。这是固定样例的工作量证据，不是 1/5/10 MiB 文档的视口扩展性或输入尾延迟结论。
