# `==文本==` 行内高亮设计

状态：设计，尚未实现。日期：2026-11-14。

本方案基于当前工作区代码。高亮作为 Ryne 的可选解析扩展，编辑器默认启用；原始 Markdown 仍是唯一数据真相。首版提供固定 `#FFFF00` 的黄色背景，接入现有行内显隐、补全、撤销、保存和 PDF 导出。

## 1. 用户行为

- `这是==重点==。` 在阅读状态显示“这是重点。”，仅“重点”有高亮背景。
- 点击或方向键进入高亮后，显示可编辑的两侧 `==`；正文保留高亮，标记使用现有弱化标记色、不涂高亮背景。离开后收起；悬停不展开。
- 嵌套在粗体、斜体、删除线或链接文字中时，沿用现有行内祖先展开规则。列表、引用、表格等外层结构继续保持呈现。
- 全文或局部源码模式完整显示 `==`，该范围不绘制高亮背景，输入保持字面行为。
- 无颜色选择器、新工具栏按钮或新快捷键；直接输入即可使用。首版不提供跨块批量“切换高亮”命令。

## 2. 语法规则

### 2.1 配对与范围

1. 开始、结束标记均为恰好两个连续 ASCII `=`。三个及以上连续 `=` 整段不参与高亮配对，不从中截取两个。
2. 正文非空，紧邻开标记之后、闭标记之前的字符不能是 Unicode 空白；正文内部允许空格。中文、英文、数字、emoji 均可。
3. 不限制标记外侧必须是空格或标点，因此 `前==重点==后`、`a==b==c` 都有效。需要字面相等表达式时使用代码或转义。
4. 首版仅支持同一物理行、同一行内容器内的配对；LF、CRLF、裸 CR、软换行、硬换行及表格 `<br>` 都是边界。自动折行不是源码换行，照常逐视觉行绘制背景。
5. 不跨段落、标题、列表条目或表格单元格。引用／列表中的正文按各自实际行内容器识别，不包含容器前缀。
6. 从左到右配对：无待配开标记时，仅接受右侧紧邻非空白的标记；有待配开标记时，下一个左侧紧邻非空白且结构合法的标记优先关闭。无法关闭的标记保留原文；到边界仍未配对的开标记也保留。高亮不嵌套自身。
7. 标记前连续反斜杠为奇数时，该标记被转义，不参与配对；遵循现有转义呈现规则。只扫描原始源码中的 `=`，不把 `&#61;` 等实体解码结果识别为标记。

### 2.2 与已有语法组合

已有块结构优先：`标题\n==` 继续是 Setext 标题，独立的 `==` 或 `====` 不会成为空高亮。

允许高亮与粗体、斜体、删除线、链接文字形成完整嵌套，例如 `==**重点**==`、`**==重点==**`、`[==重点==](url)`、`==[链接](url)==`。交叉而非嵌套的边界不创建高亮，相关等号保留为文字，已有格式仍按原解析结果呈现。

代码和公式内部是字面区域，不扫描 `==`。外层高亮可以完整包含行内代码或行内公式，例如 ``==调用 `foo()`==``、`==结果 $x$==`，但不能以它们内部的等号作为配对标记。公式作为完整原子对象参与背景和选区绘制。

链接地址、标题属性、引用定义、图片节点及原始 HTML token／HTML 块不扫描高亮。首版不接受跨图片或原始 HTML token 的高亮配对；这些节点作为配对边界。HTML token 之间由现有解析器识别的普通 Markdown 文本仍可单独包含高亮，不增加 HTML DOM 解析。

| 源码 | 预期 |
| --- | --- |
| `==重点==`、`前==重点==后` | 正文高亮 |
| `==重要 内容==` | 内部空格同样有背景 |
| `== 重点==`、`==重点 ==`、`== ==` | 不创建高亮 |
| `==未完成`、`====`、`===重点===` | 等号保留为文字 |
| `\==重点==` | 不创建高亮 |
| `==甲== ==乙==` | 两个独立高亮 |
| `==甲====乙==` | 中间四个等号为正文；外侧配对形成一个高亮 |
| `==甲` + 源码换行 + `乙==` | 不跨行配对 |
| `==**重点**==`、`**==重点==**` | 高亮与粗体叠加 |
| `**==甲**乙==` | 交叉边界，不创建高亮 |
| 行内代码中的 `==文字==` | 字面代码，无高亮节点 |
| `$a==b$`、围栏代码内 `==文字==` | 公式／代码按原规则处理 |
| `[文字](https://example.org/?q===a==)` | 地址不解析高亮 |

## 3. 输入、编辑与历史

沿用当前“首个正文字符触发补全”策略：

```text
输入 =      → =│
再输入 =    → ==│
输入 文     → ==文│==
继续输入 字 → ==文字│==
再输入 ==   → ==文字==│
移出        → 收起标记，显示高亮正文
```

- `│` 仅表示光标，不进入源码。输入首个正文字符与补出闭标记是一次事务；一次撤销退回 `==`。
- 仅在空选区、渲染模式、有效文本上下文中尝试补全；首个空白、换行或第三个 `=` 不触发。已存在闭标记时不重复补出。
- 先构造候选源码，再用同一解析配置确认产生范围精确匹配的 `Highlight` 节点；不能改变相邻 Setext 标题、跨语法边界或吞入相邻内容。已被块语法占用的 `==` 不作为输入草稿开标记。
- 自动闭标记复用现有 closers 状态，可以逐个 `=` 越过；越过不修改源码、不新增内容撤销记录。编辑、移动和历史恢复继续按现有状态映射验证它。
- IME 预编辑期间不补全、不切换显隐；确认正文和闭标记一起提交。候选确认 Enter 不额外换行。
- 粘贴完整 `==文本==` 后正常解析。高亮新增规则只对键入及 IME 确认补全；粘贴、文件加载及历史重放不凭空增加等号，利用现有 `InputOrigin` 区分。
- 删除一个等号导致配对失效时，剩余源码直接显示；不自动修复、不删除正文。Backspace 不引入整对删除特例。
- Enter／Shift+Enter 保留所在段落、列表、引用、表格的现有命令。实际插入源码换行或 `<br>` 后，跨边界的高亮失效并显示原有等号，不自动拆成两个高亮。
- 拖选及组合输入沿用现有显隐冻结；跨范围选择、替换、剪切和复制使用现有源码映射。完整范围的源码复制包含 `==`，不新增富文本剪贴板格式。

## 4. 视觉与主题

新增语义颜色 `highlight_bg`，不使用代码高亮的 token 配色。按用户指定，渲染背景固定为不透明的 `#FFFF00`，亮色、暗色主题均使用该值，不随主题调色。正文沿用当前文字颜色，粗体、斜体、删除线和链接下划线继续叠加。

- 背景不增加水平内边距、不修改字体、字重、字距或行高，因此不会因背景本身改变折行。
- 按本帧排版的实际文字片段绘制；自动折行逐行着色，不跨行填满空白区域。字号和缩放变化使用对应片段的实际高度。
- 背景层次为块背景 → 行内背景 → 选区 → 文字／公式 → 光标与预编辑标识；选区必须清楚可见。
- 同一文字同时是高亮和行内代码时，高亮替代代码灰底，保留等宽字体；公式保持原有字形和基线，背景覆盖完整公式占位。
- 显示出来的高亮标记、嵌套格式标记及链接地址等语法字段不着高亮色。内容高亮与语法可编辑性分别处理。
- PDF 同样使用固定 `#FFFF00` 背景，正文仍可选择，公式仍为矢量。

## 5. 实现分层

### 5.1 解析器：权威语义和无损标记

在 `ryne-parser` 增加 `NodeKind::Highlight`、`SyntaxKind::Highlight` 和显式扩展开关。建议引入包含 dialect、math、highlight 的解析配置及 Ryne 编辑配置，原 `new`／`with_dialect`／`with_math` 保留原含义；固定 GFM 样例不开启高亮，编辑器配置启用数学与高亮。

保持当前依赖锁定，在仓库自有解析器内实现扩展，不依赖 UI 正则替换：

1. 完成已有块结构及行内语义解析后，在允许的行内范围中扫描原始等号，跳过字面区域和不允许的边界。
2. 配对必须形成合法树：两端能在同一个行内容器的子序列中切分，内部已有节点只能被完整包围。对内部的粗体、链接等容器递归处理，接受内外两种完整嵌套；拒绝交叉边界。
3. 只在源文和语义文本直接对应的文字位置切分；转义、实体等 Transform 保持完整原点映射，不能把解码后的字符串位置当源码偏移。
4. 为高亮创建包含两侧标记的 envelope、正文子节点及两个各 2 字节的 OpenMarker／CloseMarker。保存仍串接原始源码，不重新生成 Markdown。
5. 在建立 lossless syntax、field origins 和查询索引前完成树重建。当前 ledger 按节点顺序声明归属，必须保持父先子后的顺序；统一重建节点 ID，并重映射 parent、children、reference users 等所有关联，不能简单尾部追加父节点。
6. 高亮扫描及重建以源码、节点、候选标记总量为界，避免对每个候选重新解析整段或反复全树扫描；需要祖先判定时预建深度／区间索引。异常或无法安全切分时保留字面等号。

自有 HTML renderer 将启用扩展的高亮节点输出为 `<mark>…</mark>`；继续转义正文并沿用 HTML policy。诊断用后端 HTML 及默认 GFM 导出接口不承诺解释该扩展。

### 5.2 解析配置必须贯穿所有重建

不能只修改第一次打开文件的解析入口。`ryne-syntax/src/snapshot.rs` 的裸 CR 视图、session 编辑发布、输入补全候选、parser planner 重解析、排版语义等价校验、历史恢复和导出快照均继承相同配置。建议提供“按当前快照配置重解析”的内部入口，避免硬编码 `with_math` 漏启高亮。

解析配置参与语义缓存身份；同一源码使用不同配置时不能复用错误的投影。首版没有面向用户的动态开关。

### 5.3 呈现、输入和窗口

| 层／位置 | 计划变更 |
| --- | --- |
| `ryne-syntax/src/snapshot.rs` | 将 Highlight 加入 inline_nodes 索引，沿用快照范围查询 |
| `ryne-features/src/presentation.rs` | 接入 editable_inline、祖先显隐和标记隐藏；只给正文贡献高亮属性 |
| `presentation/style_plan.rs` | 增加 `Attr::Highlight`，更新属性计数、style 写入和 resolve；避免遗漏当前固定的属性数组长度 |
| `ryne-projection/src/lib.rs` | 增加 `Style::highlight: bool`，由已有 span 携带；不新增可编辑正文副本 |
| `ryne-features/src/input.rs` | 支持宽度恰为 2 的等号，候选必须是 Highlight；保护现有 marker 和字面上下文 |
| `commands/inline.rs` | 接入 InputOrigin 限制，复用补全、closers 和统一事务 |
| `ryne-parser/src/planner.rs` | 审计已有强调类处理、重解析和编辑验证，对高亮使用等价的结构保护 |
| `ryne-ui/src/theme.rs`、`text_layout.rs`、`paint.rs` | 明暗主题的 highlight_bg 均设为 `#FFFF00` 并处理背景优先级，普通文字复用 TextRun 背景，公式使用原子几何补齐背景 |
| `ryne-services/src/print_layout.rs` | 普通文本、表格单元格和公式分支均输出高亮背景；PDF 编码器不重新解析等号 |

新增 Style 字段须同步所有构造、拷贝、比较、布局缓存签名、测试用 legacy 呈现及公式样式继承。现有主题缓存键继续生效，不能因缓存未包含高亮差异而显示旧背景。

“排版”命令将高亮视为语义结构，不转换为 HTML，不规范成其他标记，不为未闭合高亮补齐。合法的周边排版必须保留高亮树、正文和原始换行；候选语义改变时整次拒绝。

## 6. 验收与交付顺序

1. **解析与范围**：覆盖上表、链接引用、转义奇偶、实体、中文／emoji／组合字符、交叉格式、Setext；对 LF／CRLF／CR 验证标记范围和源码逐字节往返。原有未启用扩展的 GFM 基线不变。
2. **会话与投影**：覆盖首字补全、IME 确认、粘贴、逐字符越过、删除标记、一次撤销／重做、源码模式；验证显隐及主题切换不改变源码、dirty 或历史，双向映射及 grapheme 边界有效。
3. **结构组合**：普通段落、H1–H6／Setext、嵌套列表、引用、表格单元格内显示与直接编辑；代码、公式、URL、图片和原始 HTML 的边界保护；表格 Tab／Enter 行为不变。
4. **窗口与导出**：明暗主题、字号、窄窗自动折行、跨格式选区、公式混排、IME 位置、滚动及缓存复用；PDF 分页、表格、公式背景与可选择正文。检查背景不改变文字度量。
5. **规模与回归**：长单行、多未闭合等号、大量格式节点不出现重复全量扫描；实施后按影响运行架构检查、fmt、测试、clippy 和真实窗口冒烟。GUI 冒烟失败正常返回，不穿过 AppKit panic。

按“解析与范围 → 输入和呈现 → 窗口与 PDF → 回归与说明”实施。交付时更新七语言欢迎指南、两份 README 和 AGENTS 的已实现说明；本设计阶段不将功能记为已完成。

首版边界：单色、单物理行、可组合的行内高亮。跨源码换行、颜色参数、跨块切换高亮命令均不纳入本次。
