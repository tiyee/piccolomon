# 大文件优化 P1/P2 实施记录

日期：2026-10-15。设计基线为 `docs/31_Large_File_Optimization_Design.md`，
改造前诊断见 `docs/30_Large_File_Performance_Assessment.md`。
只实施共享索引、查询、区间组合与可见装饰/绘制；没有升级依赖或替换源码事务。

## 实现

### 共享语义快照

`ryne-syntax::ParseSnapshot` 是锁定解析器快照的只读适配器，通过 Deref 保留只读 AST 访问，
原始解析器 Source 身份与字节不变。它持有 OnceLock 索引与结构查询结果，
随源码快照释放；没有全局按文本缓存，也不把相同内容当成相同文档身份。
需要裸 CR 兼容时，同一快照只保留一份等字节宽的规范化语义视图。
规范化视图有自己的内部 Source 身份，不替代已提交的 Source。

`SemanticIndex` 共享物理行、按类型节点、容器 token 与增广区间目录。
代码块的首末行、正文行及前缀，表格的行/单元格及容器，以及列表行的最内层条目归属
改用二分、区间查询和有界顺序扫描；引用尾行查询共享同一行/token 目录。
`SemanticQuery` 返回缓存切片，兼容的 `blocks/items/rows/tables` Vec 接口仍可按需生成拥有值。
内置导航/呈现和主要输入热点借用缓存结果；查询不会重新全文解析或重建行数组。

内联显隐从当前位置的候选内联范围取得祖先，标题和围栏草稿使用节点目录。
全文源码模式跳过没有显示作用的列表、引用和 flow 构建，并跳过光标显隐计算；
代码高亮、字面输入及已有资源限制继续保留。

### 不可变展示索引

可变 `Display` 继续用于构建、扩展贡献和导出；完成验证后，发布为不可变 `IndexedDisplay`。
后者只有只读 Deref，没有 DerefMut，内部映射、grapheme、flow/list/quote 索引与文字一起冻结。
避免在仍有公共可变字段的 Display 上缓存可能过期的查询结果。
会话缓存与 UI 几何共享 `Arc<IndexedDisplay>`，源码身份/投影代次检查仍由会话及帧边界执行。

源码/展示 span 查询改为有序二分；表格边界/空单元格、引用末尾空行使用独立锚点目录，
保留原始顺序、EOF 及 Upstream/Downstream 的优先级。
投影生成结构范围时一次建立 MappingIndex，避免为每个块重复扫描所有 span/单元格。
紧列表的 flow 范围先计算条目末端与已有覆盖，避免逐项交叉扫描。

发布投影按完整最终可见字符串构建 grapheme 位图与非空字目录，支持前后边界、最近位置和删除。
位图约为可见文本字节数的 1/8，另有非空字目录；没有为每个 ASCII 字符保存一个 usize。
普通可变 Display 的短期查询使用 GraphemeCursor，就近查询并提供完整 Unicode 上下文，
不依赖固定重叠长度；保留正确的全字符串分段回退。
跨 span 的结合符、ZWJ、区域指示符和超长 grapheme 不按人为分块截断。

### UTF-16 与预编辑范围

源码快照保存约每 4096 字节一个合法字符边界的 UTF-16 累计检查点，转换先二分再扫描局部。
会话的临时范围转换以基础源码检查点和单一预编辑替换区间组合计算，不需要拼接整文。
没有预编辑时 `editable_text_cow()` 借用 Source；输入桥接改用会话的范围转换接口。
预编辑文本仍不进入历史，确认一次事务，非法代理对中部位置仍拒绝。
IME 的临时语义/投影仍全文构建，P5 的局部临时投影尚未实现。

### 区间式样式与可见区域

`StylePlan` 将有序的单属性赋值转换为端点事件，按活动赋值的先后顺序解析区间。
保留原有组件覆盖顺序，包括代码高亮、标题/内联显隐、列表/引用前缀、表格替换、公式字面内容
及局部/全文源码覆盖；删除一个活动区间时不会丢掉尚有效的外层属性。
按区间生成文字、样式和映射，取消生产路径中的逐字节 Style/hidden 数组。
原有逐字节构建只保留为测试 oracle，不在正式刷新中双算。

正文仍完整精排一次；在不可变 TextLayout 中保存 source-range 和 Y 区间目录。
代码面板、列表标签/任务标记、单元格边框、前置控件、引用背景、选区和文字绘制
只查询与当前视口相交的几何；重叠表格行带保持原始顺序。
选区仍覆盖完整源码，裁剪只影响绘制；复制、替换和跨块选择不依赖可见子集。
引用入口/图标不按视口重复，巨大背景继续使用同一外层引用范围。

标题表头、列表行、引用和 flow 的排版查询复用索引，引用背景首末行使用有序行范围。
控件预留宽度只在 ControlIndex 更新时计算；控件批次代次进入 LayoutKey，
防止相同预留宽度但控件身份改变时复用错误的可见目录。
滚动复用文字排版；字体、宽度、显隐、源码或资源变化沿用既有失效规则。

## 正确性验证

- 可见文字、样式、结构范围与资源：以保留的旧逐字节构建为 oracle，
  遍历小语料的所有合法 UTF-8 光标位置、源码模式、标题展开及局部源码范围，比较完整 Display。
- 索引对照：双向映射与原线性算法对比，覆盖空单元格和引用尾锚点；
  区间查询对比重叠扫描，保持重复范围和边界顺序。
- Unicode：grapheme 位图与完整分段比较，覆盖 ZWJ、组合音符、区域指示符、跨字符偏移、
  超过 16 KiB 的结合序列和 EOF；平台范围检查点与旧 UTF-16 转换对照。
- 表格：二分最近单元格查询对照完整扫描，覆盖分隔线、空单元格及等距优先级。
- 会话：预编辑替换覆盖的 UTF-16/UTF-8 范围对照临时文本，检查原始源码、历史和 dirty 不变。
- 窗口：既有完整冒烟继续覆盖列表/表格菜单、代码语言入口、公式/引用、旧帧保护及 IME 回调。
  新增专项检查覆盖视口裁剪、滚动排版资源复用、CRLF/Unicode 范围及预编辑几何。

专项入口：

```sh
RYNE_SMOKE_PERFORMANCE_ONLY=1 cargo run --locked -- --smoke-test
```

它使用约 80 组混合块的真实窗口，不能描述为完整人工鼠标、各输入法候选或 10 MiB GUI 验收。

## 性能复测

与改造前相同的 x86_64 macOS / i7-8750H / Rust 1.99、locked release 构建，
运行时不并行编译、GUI 或其他基准。原始数据在 `docs/reviews/large-file-perf/p1-p2/`，
保留改造前父目录记录。实际目标字节数稍高于 1/5/10 MiB，因为重复完整语料单元。
普通段落和长单行各 3 个样本；结构诊断及大规模格式/引用各 1 个样本，均无预热。
这些是无窗口阶段测量，没有 P95/P99 或真实窗口 10 MiB 端到端延迟保证。

| 场景 | 改造前完整投影 ms | P1/P2 完整投影 ms | P1/P2 投影及发布索引 ms |
| --- | ---: | ---: | ---: |
| 普通段落 1 MiB | 61.55 | 36.43 | 66.62 |
| 普通段落 10 MiB | 608.19 | 372.79 | 693.51 |
| CRLF 普通段落 1 MiB | 1516.27 | 41.77 | 72.11 |
| 嵌套列表 256 KiB | 4425.53 | 110.47 | 101.62 |
| 独立引用 256 KiB | 10267.92 | 67.06 | 69.05 |
| 小代码块 256 KiB | 1386.38 | 23.70 | 26.56 |
| 小表格 256 KiB | 1511.41 | 113.31 | 116.14 |

完整投影指标不包含新发布索引的构建，故单独列出后者；不能把一个缓存命中当作完整刷新。
两项各自测量，少量样本可能出现“完整投影”比“投影及索引”更慢的波动，不能据此推断索引没有成本。

10 MiB 普通段落末尾选择、光标规范化及 grapheme/UTF-16 热查询已降至微秒级，
缓存 key 查询不再全文扫描。该指标不含新的显隐投影、排版、绘制、首次索引建立或系统输入事件。
输入提交最终中位数 1258.99 ms，改造前为 1087.03 ms；全文解析本轮为 993.45 ms，
基线为 667.70 ms。当前结果不能证明输入端到端提速，源码修改仍付出全文解析和新版本索引成本。
开发过程另一轮输入约 840 ms，说明绝对值存在明显运行波动；最终表格以保存的最终记录为准。

新增 1/5/10 MiB 格式密集段落与引用诊断，没有把 256 KiB 的结果外推成 10 MiB。
10 MiB 格式段落完整投影约 2208 ms、输入约 3591 ms；独立引用完整投影约 3147 ms、
输入约 5761 ms。结构越密集，全文派生与分配成本仍明显，需要 P3–P5。

64/128/256 KiB 的小代码块、列表、表格和引用已不再出现原来的显著平方扫描。
单样本增长比受分配和缓存拐点影响，引用 128→256 KiB 一轮为 2.66 倍，
不能把它描述为已稳定通过设计中的 2.5 倍趋势目标；绝对耗时与全部原始样本同时保留。
另追加每项 3 个样本的四组趋势复测（`trend-*.jsonl`）：列表的两个翻倍比为 1.62/1.88，
代码为 1.87/1.83，表格为 2.46/2.18，引用为 2.06/2.58。引用仍略高于预设阈值，
保留为后续压测项；端点排序和按块二分查询仍含 O(K log K) / O(B log S) 成本，
不把这些结果描述为所有结构均严格线性。

内存：最终普通段落基准进程峰值 RSS 约 794.5 MiB（基线约 773.8 MiB），长单行约 338.8 MiB，
10 MiB 密集引用组约 2792.2 MiB。此为整组无窗口进程，包括基准持有的快照、临时解析及发布索引，
新基准也比旧基准多了发布索引测量阶段，不能作为同口径 GUI 内存改善证明。
生产投影取消了约 120 MiB/10 MiB 的逐字节 Style 数组，但新索引也占空间，解析峰值仍存在，
因此不宣称总体 RSS 已下降。互不重叠的区间使用二分目录，不再分配增广树，降低常见正文的索引开销。

## 保留限制

内容修改、撤销及 IME 临时状态仍全文解析；新的派生索引会按版本重建。
正文仍全文精排，尚未交付块排版缓存、估计高度、局部语义更新或局部 IME 投影。
正文鼠标复杂命中和其他结构命令仍有继续优化空间；P1/P2 不等于所有交互都已与文档长度无关。
兼容的拥有值查询可以复制结构，主路径复用不能被解释为任意调用均零分配。
索引为当前快照拥有的线性/排序数据结构，未新增跨文档 LRU 或承诺 128 MiB 总 RSS。
当前图表、字体、高亮、排版与 PDF 导出限制保持原样，保存不格式化、不改换行字节。

## 最终检查

通过 `python3 scripts/check-architecture.py`、`cargo fmt --check`、`cargo test --locked`
（238 项测试）和 Rust 1.99 的全目标 Clippy 零警告检查。
本机 `cargo-clippy` 默认解析到旧驱动，因此实际使用
`/usr/local/opt/rust/bin/cargo-clippy clippy --locked --all-targets -- -D warnings`，未修改全局配置。
完整真实窗口冒烟和 P1/P2 专项冒烟通过；失败注入返回预期退出码 1，无原生事件循环 panic。
14 组最终性能运行及 4 组趋势复测全部完成，原始数据包含 43 份语料配置。
以上窗口验证在本机 macOS 执行，未进行 Windows 桌面和人工各输入法候选窗口验收。
README 两种语言、AGENTS 当前实现说明及设计提案状态同步更新。

调试包通过 `sh scripts/bundle-macos.sh debug` 原子更新至 `target/Ryne.app`，保留当前窗口运行状态。
