# 10 MiB 大文件优化方案、可行性与风险

状态：P1/P2 已实施，见 `docs/32_Large_File_P1_P2_Implementation.md`；P3–P5 仍为设计提案。日期：2026-10-15。
依据：`docs/30_Large_File_Performance_Assessment.md` 及其 release 基准原始记录。
范围：当前 Rust/GPUI 桌面编辑器，保留 Markdown 就地编辑、统一源码事务及既有依赖锁定。
本次仅编写方案，不修改生产实现、用户已有工作或发布配置。

## 1. 决策结论

建议分两条连续路线交付：

- 第一条优化现有同步架构：共享语义索引、源码/显示映射索引、grapheme 边界索引、
  源码模式快速路径、可见装饰生成、区间样式构建和块级排版缓存。
  可行性高，能先消除已确认的平方路径，并显著改善导航、滚动和首次显示。
- 第二条改造编辑后的语义与展示更新：引入可替换的语义快照后端、保守的局部更新、
  分块投影和 IME 临时覆盖层。可行性中等，改动较大，但要达到 10 MiB 连续输入目标，
  这一条不能被缓存、异步化或防抖替代。

现有 10 MiB 普通段落全文解析中位数约 668 ms，输入提交约 1087 ms。
第一条路线继续全文解析，因此不能承诺输入降到 100 ms。
代码扫描显示约 110 处直接访问解析器 nodes/syntax 的位置（文本匹配量，并非精确迁移工作量）；
第二条路线需要逐步替换这些依赖，不能作为一个小补丁完成。

不优先更换 rope、不升级 GPUI/解析器、不引入第二份可编辑正文，也不默认关闭结构呈现。
实现中若发现现有解析 API 无法支撑语义更新，先完成独立原型与差分验证，再决定后续投入。

## 2. 目标、测量口径与交付边界

### 2.1 拟定性能目标

下表是研发验收目标，尚无实现结果支撑。以现有 Intel 本机的 release 构建为首个参照，
P0 补充真实窗口测量后校准；另在 Apple Silicon 和 Windows 分别验收。
10 MiB 指约 10,485,760 字节，记录实际行数、块数、span 数及嵌套深度。

| 场景 | 完整方案拟定目标 | 条件 |
| --- | --- | --- |
| 光标导航到下一帧可见 | P95 ≤ 16 ms，P99 ≤ 33 ms | 已加载文档；含可见区域显隐更新 |
| 稳态滚动帧的主线程工作 | P95 ≤ 16 ms，P99 ≤ 33 ms | 缓存热；包含布局、装饰及绘制提交 |
| 普通输入到更新后的正文可见 | P95 ≤ 100 ms，P99 ≤ 200 ms | 普通正文、有效代码正文及常见内联局部编辑 |
| IME 预编辑更新到可见 | P95 ≤ 50 ms | 当前编辑区域已精排；不含系统候选窗口内部耗时 |
| 打开到可交互首屏 | P95 ≤ 3 s | 本地普通段落/典型混合文档；同时报告文件读取与派生计算 |
| 保存、撤销、选择和源码映射 | 正确性零回归 | 原始字节、LF/CRLF/CR、事务边界和身份一致 |

改变围栏、容器层级、引用定义或其他全局语义的编辑可以触发全量回退，单列延迟，
不能混入普通输入统计，也不能丢掉这些编辑。超深嵌套、超长 grapheme、极宽表格等
必须保留可编辑结果与资源保护，不对所有对抗性文档承诺相同延迟。
首次打开、首次远距离跳转和冷缓存滚动单独报告，不能用热缓存指标覆盖。

### 2.2 阶段完成标准

P1/P2 的主要目标是消除重复/平方扫描，规模翻倍时的索引与投影构建趋势应接近线性，
初定对相同结构语料的 2 倍规模增长比不超过 2.5；分配器/缓存拐点需要重复测量解释。
这只是趋势门槛，同时必须保留绝对耗时、峰值内存及完整样本。
P3 完成热导航/滚动目标；P4/P5 完成普通输入/IME 目标后，才可宣称 10 MiB 编辑目标达成。

不在此方案中扩大现有 PDF 4 MiB 导出限制、排版 1 MiB 限制、图表/高亮资源预算，
也不顺带实现完整 Bidi、辅助功能或出版级分页。

## 3. 架构与所有权

```text
ryne-core       原始 Source、PreparedEdit、统一历史/保存基线
    ↓
ryne-syntax     SemanticSnapshot + SemanticIndex；全量/局部语义后端
    ↓
ryne-extensions 只读快照、显式稳定性/失效依赖契约
    ↓
ryne-features   命令准备、语义块贡献、上下文依赖声明
    ↓
ryne-session    候选验证、原子发布、派生快照与任务生命周期
    ↓
ryne-ui        按视口精排、命中、IME 几何与绘制

ryne-projection 持有平台无关的映射/投影值与查询索引
ryne-services   继续提供公式、图表、高亮和文件服务
```

以上为数据流概览，生产依赖仍遵循既有分层检查，不新增 syntax → session/UI 等反向依赖。
所有新索引和缓存都只读、可丢弃；不能独立编辑，也不能成为历史或保存的数据来源。

拟新增的核心概念（内部设计名，不表示已存在的 API）：

| 概念 | 所属包/所有者 | 身份与用途 |
| --- | --- | --- |
| `SemanticIndex` | syntax 定义；只读快照持有 | 原始文档身份 + 语义代次；行、节点、容器和结构查询 |
| `ProjectionIndex` | projection | 对应投影代次；双向映射、特殊锚点、grapheme、flow |
| `SemanticSnapshot` | syntax 定义；session 发布 | 封装完整语义后端，避免业务依赖扁平解析器存储 |
| `BlockProjection` | projection/features 生成，session 缓存 | 派生只读块文本与局部映射、样式、资源 |
| `BlockLayout` | UI | GPUI 排版资源及块内几何；没有可变文档状态 |
| `HeightIndex` | UI viewport | 块/内部切片高度、前缀和、视口定位与滚动锚点 |
| `CompositionOverlay` | session | 基础源码身份 + 预编辑代次 + 单一替换范围 |

渐进迁移：先给 `EditingState` 增加与 parse 同源的索引入口，保留现有 ParseSnapshot 适配；
原子发布同时验证 source、parse 和 index 对应同一候选源码。
P4 才将业务迁移到 SemanticSnapshot 接口，不能提前把旧 parse 标成新文档版本。
新的语义接口仅服务当前静态功能，沿用解析器的语法含义，不扩大为动态插件 SDK。

## 4. P0：补齐真实窗口基线

建议工作量：1–2 人日。风险低。

保留现有无窗口基准，增加阶段计数与真实窗口 tracing：

- 输入事件 → 命令准备 → 事务准备 → 解析/索引 → 原子发布 → 投影 → 布局 → 绘制提交。
- 光标操作记录查询次数、缓存命中和显隐失效范围，滚动记录精排行数与装饰数量。
- 记录实际 GUI 峰值 RSS、缓存字节、在途快照、后台任务队列长度及取消任务耗时。
- 已有 `RYNE_PROFILE` 增加细分作用域；计时与日志默认关闭，事件回调内不 assert/panic。

语料覆盖 1/5/10 MiB：普通短段落、格式密集段落、嵌套列表/引用、一个大表格、
很多小表格、单个长代码块、很多小围栏、10 MiB 长单段及混合文档。
每类包含 LF/CRLF/CR；现有诊断只有部分结构的 64–256 KiB 数据，不能冒充 10 MiB 验收。
为慢路径设置外部运行时限并记录未完成样本，不能把超时从统计中直接删除。

性能对照保持同机、同构建类型、相同功能和语料，避免后台编译/并发基准干扰。
差分正确性先用小文档穷举/随机编辑，大文件性能分别测量，避免校验本身掩盖收益。
P95 至少收集 100 个稳态样本；P99 至少 1000 个，并保留多轮数据和分布，样本量不是置信保证。
真实输入法候选交互另外人工验收；窗口冒烟只证明回调/几何通路。

## 5. P1：共享索引与查询改造

建议工作量：5–8 人日。可行性高，正确性风险中等；无需新依赖或改变源码事务。

### 5.1 语义索引

每份解析快照构建一次不可变基础索引，物理行保存 start、正文 end、换行 end，
准确区分 LF/CRLF/CR；类型节点建立有序目录。容器 token 按源码位置和 owner 分组，
列表条目保存父子/同级关系，表格与代码块共用物理行查询。
裸 CR 检测每份源码一次；需要规范化解析时保留一份等字节宽的内部语义视图。
规范化 Source 的内部身份不能冒充原始 Source：对外范围始终绑定原始文档，由适配器验证转换。

基础索引 O(N + A + T) 构建；某些目录排序允许 O(A log A)，不得重新出现每行 × 全部节点。
N 为字节，A 为节点，T 为 token。类型为空时直接返回空切片，不建立无用完整结构。
代码首末行、表格行、列表行归属、引用尾行通过二分/区间扫描定位。
列表嵌套使用活动容器栈或区间事件选择最内层；token 只查询与当前行相交的区间。
`active_window()` 从当前位置所在内联范围取得祖先链，保留当前祖先标记展开语义。

旧 helper 在迁移期保留为显式全量对照入口，热路径必须传共享快照/index；
不能让兼容 helper 每次在内部偷偷新建索引，形成另一种重复构建。

### 5.2 源码与显示映射

span 输出稳定后建立有序查询；source→display、display→source 分开处理。
在生成 flow/代码/列表等展示范围时复用同一个索引，顺序批量映射使用递增游标。
完整投影冻结后再发布与其身份绑定的 ProjectionIndex。

特殊边界单独建目录：空表格单元格、引用尾空行、隐藏前后缀、公式和图表原子区间。
同起点、同终点、EOF 和 Upstream/Downstream 的优先级必须逐项等价于旧实现。
索引只建立在已验证的单调范围上；非单调贡献拒绝/回退，不能排序后改变业务含义。
源码模式跳过不用的结构提取与 flow 生成，同时保留源码高亮、语言识别预算和字面输入。

### 5.3 grapheme 与 UTF-16

第一版按最终展示字符串连续分段一次，建立边界位图及非空分块目录。
10 MiB 文本的位图约 1.25 MiB；避免为每个 ASCII 字符存一个 usize，额外消耗约 80 MiB。
边界含 0 和 EOF，最近边界等距时沿用旧实现偏左的规则，删除查询复用前后边界。
不能把 span/任意固定字节切片当作 Unicode 分段边界；ZWJ、组合音符、区域指示符必须连续处理。

初期边界索引仍全量构建一次，只降低重复导航成本，不宣称消除了每次输入的 O(N) 工作。
UTF-16 索引绑定原始源码，在每行或定长块的合法字符边界保存累计值；查定位点后只扫描局部。
无预编辑时输入回调借用 Source，避免整文 String；预编辑用单替换覆盖视图转换范围。
拒绝代理对中部和 CRLF 拆分的规则保持不变，索引不存在时使用原有正确转换。

### 5.4 验证与收益边界

对全部合法字节边界/affinity 比较新旧映射；随机隐藏区间、重复锚点、跨 span grapheme、
容器前缀与三种换行必须覆盖。比较代码/表格/列表/引用提取的完整结果。
检查旧索引无法查询新源码；导航不产生历史/dirty。
预计收益主要来自移除引用/列表/代码/表格和 CRLF 投影的交叉扫描；具体倍数待实测。

## 6. P2：区间式投影构建与可见装饰

建议工作量：4–7 人日。可行性高，风险中等。

逐字节 Style/hidden 改成有序区间事件：组件贡献带范围、属性、优先级和稳定顺序，
组合器按端点扫描输出最终样式/可见性区间，再一次生成文字和映射。
必须复现现有覆盖顺序，尤其是内联展开、列表/引用前缀、代码字面内容、表格替换和局部源码覆盖。
区间贡献多时复杂度目标 O(K log K + N)，K 为事件数；嵌套属性用可移除的活动集合，
不能删除内层样式时顺带删除仍有效的外层样式。
这是移除约 120 MiB/10 MiB 逐字节 Style 数组的确定结构性机会，峰值 RSS 的改善须另测。

flow/list/quote/table 的查询建立区间目录；构建排版前后不再逐行扫描所有块。
先保留全文精排结果，仅按视口 Y 范围生成背景、列表标签、表格边框、控件及选区四边形。
可见引用片段沿用外层统一背景和入口，quoter 仅在原始起始正文处出现，不按视口重复。
代码语言标题离开屏幕后不生成其标签，不引入未要求的吸顶行为。
选区数据继续覆盖全文，裁剪只影响绘制；复制/替换仍通过完整源码范围执行。

控件预留宽度的布局代次只在其内容改变时更新，LayoutKey 不再每帧重建所有预留值。
图表/公式继续沿用服务缓存和限制，未知扩展仍执行全量安全路径。
小语料逐字段对比投影；真实窗口核对菜单、任务标记和面板边界，截图对比同一可见区域。

## 7. P3：块级排版缓存与视口虚拟化

建议工作量：10–18 人日。可行性中高，几何/滚动风险高。

### 7.1 稳定块与失效依赖

块缓存键采用会话内稳定 BlockId、内容代次、容器上下文、显示模式/显隐代次、
列宽/阅读栏宽度、字体/缩放、控件预留宽度及资源代次。
节点数组序号和绝对源码起点不能单独当作跨版本稳定身份；前方插入会改变它们。
迁移期可用连续未改区间匹配 + 字节比较确认块身份，hash 仅用于候选筛选，不能作为唯一正确性证据。
一个块可能依赖父容器和相邻间距：上下文/边界间距作为明确键或独立边界贡献保存。

| 编辑/状态变化 | 至少失效的范围 |
| --- | --- |
| 普通块正文/行内显隐 | 当前块；相邻边界间距按需更新 |
| 列表移动、缩进、编号位数变化 | 当前子树、受编号/宽度影响的同级及父容器布局 |
| 引用层级变化 | 涉及的引用容器；背景范围和入口由外层重建 |
| 单元格文字 | 当前单元格与行高；列宽不变时其他行可复用 |
| 表格列对齐、增删/移动列 | 整张表格；容器上下文一并校验 |
| 围栏/语言/代码显隐 | 当前代码区域；围栏影响块边界时扩大到语义确认范围 |
| 公式/图表结果 | 使用该资源的块，不刷新无关块 |
| 字体、窗口宽度、缩放 | 布局代次全部变化；可分帧重建，但旧宽度几何不能接受新命中 |

初期仍允许全量解析与全量只读投影，复用未变块的 GPUI 排版；此过渡实现仍有 O(N) 前置成本。
P4 才取消每次编辑拼接全量投影和重建全文索引的要求。

### 7.2 高度索引与坐标

平坦的渲染单元目录配前缀高度树/Fenwick 结构，支持高度更新、Y 定位和源位置定位。
单元包含顶层块与大型块内部的行/行组切片；不能只虚拟化顶层块，否则一个大表格或长单段仍卡顿。
精排窗口为视口加上下各一屏预取，按实测调整；当前光标、预编辑范围和正在命中的单元必须精排。
未知单元高度可以估算，但只能用于滚动定位/滚动条，不得作为文本选择或 IME 命中几何。

文档累计高度及滚动位置使用 f64，进入 GPUI 时只将视口附近的相对坐标转换为 Pixels/f32。
避免 10 MiB 多行文档的巨大 Y 值造成亚像素精度丢失或减法误差。
同一表格行中的单元格可能共享/重叠 Y，建立行带索引后在带内按 X 命中，不能假设视觉行严格单调不重叠。

### 7.3 命中、滚动与长段落

滚动锚点采用源码位置 + 单元内偏移，事务后经 PositionMap 映射；高度估计更新时保持该正文位置的屏幕 Y。
未知区域被点击或远距离导航时，先对当前版本目标精排，再重新解析该输入事件的几何。
若需要等待下一帧，记录原始事件和版本令牌；版本变化后取消/重定位，不能沿用旧像素解释新文本。
拖选的逻辑选区可跨未排版区域，边缘自动滚动只扩展当前版本已精排位置。
IME 回调必须返回当前预编辑的真实几何，不能把估计框返回系统候选定位。

超长段落分片必须保持换行状态、字形 shaping 上下文和行内对象，不能按固定字节直接切 shape_text。
先原型验证单段内增量换行和可恢复的行起点，再接入虚拟化；不具备安全恢复条件时整段精排并单列慢路径。
这是 P3 的独立高风险点；10 MiB 长单段的端到端目标需要该子项完成，不能被多短块语料替代。

布局仅由 UI/GPUI 所在线程访问；后台计算只准备平台无关信息，不假设 GPUI shaping 可跨线程。
FrameToken 包含文档身份、投影代次、预编辑代次、布局参数及精排集合代次。
索引和缓存虽然允许跨版本复用底层未变数据，对外命中入口必须验证完整当前令牌。

## 8. P4：语义快照抽象与保守局部更新

建议工作量：先 3–5 人日原型，进入正式迁移后另计 15–30 人日；可行性中等，风险最高。

### 8.1 为什么不能直接拼 ParseSnapshot

现有解析包 0.0.4 的 ParseSnapshot 只提供全文构造，内部 source 字段不能由宿主任意替换。
局部解析片段具有独立 Source 身份，其局部 nodes/tokens 也不能直接冒充全局解析结果。
当前 `EditingState` 和发布验证要求 parse/source 身份一致；业务还直接读取全局数组。
因此“只解析当前行再替换几个节点”不满足既有契约。

推荐在 ryne-syntax 建立 SemanticSnapshot/查询门面，保留全量 ParseSnapshot 后端作为基线。
先把业务所需的节点种类、祖先、结构范围、内联/数学节点、token ownership 和引用解析封装进去，
然后提供分块后端。局部片段仍可使用锁定解析器解析，适配器负责把局部范围映射回原始 Source；
不能伪造它返回的文档身份，也不能在 GUI 层另写一套 Markdown 规则。

### 8.2 更新策略

采用“证明可局部更新才走快路径，否则全文更新”，按修改前后结构状态扩大脏区：

1. 利用旧快照定位修改范围与完整容器上下文，映射未改范围到候选源码。
2. 计算新旧左右边界状态；必要时扩展到完整语义块、外层列表/引用或更多相邻块。
3. 用同一解析器重解析有完整上下文的候选区域，验证容器/换行/边界状态收敛。
4. 对引用定义、引用式链接及其他非局部依赖更新依赖目录；不完整依赖追踪直接全量回退。
5. 准备语义、投影及选择状态的候选快照，验证后与 PreparedEdit 一起原子发布。

初始快路径从已确认围栏代码正文中的普通字面编辑开始，再覆盖有安全边界的普通段落。
即使在代码正文，也要检查修改是否形成闭合围栏、改变缩进或触及容器前缀。
普通段落不只检查插入字符：例如删除分隔空行、改变 Setext 下划线或修改远程链接定义都可能改变其他块。
支持结构命令的 Enter/Tab、跨块删除、粘贴、围栏编辑先走全量正确路径，验证后逐项放开。

每个持久化语义片段保存局部范围和稳定子身份，前方编辑通过索引前缀偏移调整，
不能每次把后面所有节点/token 的绝对位置加 delta，也不能复制完整 AST Vec。
使用分块不可变目录与路径复制；结构改变较小时目标为 O(修改字节 + 受影响语义 + log 块数)。
全文解析/全局语义改变仍 O(N)，明确记录回退原因、脏区大小和快路径覆盖率。

### 8.3 同时取消展示层的全量拼接

只有解析增量化仍不够：当前最终 Display 的 String、span 数组和 grapheme 位图若每次全量重建，
10 MiB 仍有数百 ms 级开销。P4 必须把投影改成只读分块目录，块内保存相对映射，
顶层按前缀字节长度提供全局位置查询；只重新生成受影响块与其依赖。
UI 经 ProjectionView 查询当前可见块及源码映射，不为一次按键 flatten 全文。
旧全量 Display 继续用于对照和需要它的后台导出适配，保留当前导出资源限制。

grapheme 分块更新需证明边界状态一致：显式换行等安全边界可隔离，跨隐藏 span 的可见串连续处理。
任意固定 64/256 字节重叠不能保证 Unicode 正确；超长结合序列须扩展至可确认边界，必要时全量重建。
长单段的增量行排版同样必须完成 P3 的上下文原型。

### 8.4 原型放行条件

在普通段落、容器代码、未闭合围栏、Setext、嵌套列表/引用、表格、引用式链接、HTML 和公式上，
随机连续编辑后与全量后端比较结构、token ownership、投影、映射、选择和保存字节。
原型不得通过扩大到全文却仍标为“局部更新”获得正确性通过。
记录实际处理字节/节点和覆盖率；普通输入快路径覆盖不足时，不能声称满足大文件目标。
如果公开 API 无法给局部解析提供等价上下文，就保持全量后端，调整目标/估算，
再形成单独的解析器协作方案；本提案不隐含授权修改、发布或升级解析包。

## 9. P5：IME 局部覆盖与后台派生任务

建议工作量：5–10 人日，依赖 P3/P4；可行性中高，输入法正确性风险高。

CompositionOverlay 只保存现有单一替换区间、候选文本和局部选择，绑定 base 文档身份与临时代次。
受影响区域建立临时语义/投影，其他块和布局只读复用；不把预编辑源码写进历史或已提交 Source。
临时 UTF-16 映射把基础索引与替换区间的长度差组合使用，选区及候选框采用同一覆盖视图。
确认候选沿用一次源码事务，确认失败保留预编辑并停止后续动作；Enter 不同时执行结构命令。
跨块平台确认或容器边界变化可退回完整临时解析，保留正确性并单列性能。

后台任务限一个执行中任务和一个最新待执行请求，按任务性质分别管理；
令牌至少含 Source 身份、语义/呈现代次、模式和资源配置，预编辑任务另含 composition generation。
结果只在完整匹配时接收，取消检查位于可中断阶段之间；已有渲染器内部不可取消的限制继续如实保留。
GPU/GPUI 资源创建与排版不跨越线程契约。

后台化先用于首次解析/只读派生和全量慢路径的准备；不允许“先发布新源码，再用旧 AST 处理结构编辑”。
普通快路径必须同步准备一致候选后发布。需要全量语义时可暂存原始输入请求、顺序处理并保持窗口响应，
但这种队列等待仍计入输入延迟，不能称为流畅输入；不得合并掉用户操作或修改撤销粒度。
设计上不保证所有全局语义变化均满足 100 ms，异步化只控制主线程阻塞和过时结果。

## 10. 内存、缓存与回退

初始新增性能缓存总预算建议 128 MiB，包括语义派生索引、投影索引和块排版缓存；
不包含唯一源码、权威语义后端、保存基线以及已有独立公式/图表服务缓存。
P0 实测后再按 Windows/Intel/Apple Silicon 调整；128 MiB 是配置起点，不是总体 RSS 承诺。
索引采用共享 Arc/分块数据，避免同一节点/容器信息在语义、投影、控件各复制一份。
Lru 优先保留视口、光标和 IME 区域；安全入口所必需的数据必须可构建，不能因预算耗尽返回错误命中。
必需工作集超预算时放弃其他缓存并报告实际占用，必要时使用有界慢路径，不靠丢正文满足预算。

在途请求和缓存不能长期保留所有历史快照；通常只持有当前、正在绘制/解析所需旧版本，
导出继续独立快照，避免一个缓慢后台任务留住大量后续版本。
测量新旧版本同时存活的峰值，而不只测稳态 retained bytes。

回退分层：查询索引异常退原始查询；贡献/投影异常退可编辑源码；
局部语义无法证明收敛退全量解析；虚拟布局无法精排时延迟该事件并生成当前几何。
不得以关闭 Markdown 结构呈现作为正常的大文件模式；失败回退只是既有故障保护。
缓存和后端开关均为内部 rollout/诊断机制，默认由已通过验收的实现选择，不增加用户操作负担。

## 11. 风险清单

| 风险 | 等级 | 影响与缓解 | 验证重点 |
| --- | --- | --- | --- |
| 映射边界优先级改变 | 高 | 空单元格/隐藏标记删除错误；逐字节差分并保留 affinity 特例 | EOF、CRLF、跨块替换、原子对象 |
| Unicode 切片边界错误 | 高 | 光标/删除截断组合字符；连续分段及状态收敛，必要时扩大处理范围 | ZWJ、长结合符、跨 span、代理对 |
| 局部语义漏掉远程影响 | 高 | 渲染/命令与原文含义不一致；依赖追踪和保守全量回退 | 引用定义、Setext、未闭合围栏、容器 |
| 旧帧或旧后台结果接收 | 高 | 点击/候选框解释错位；完整令牌检查、当前目标精排 | 连续输入中点击、取消预编辑、切换文档 |
| 高度估计与大坐标误差 | 中高 | 跳动、滚动条漂移；f64 累计、相对坐标、源码滚动锚点 | 10 MiB 文末、缩放、表格/图表延迟 |
| 长段落 shaping 无法局部恢复 | 高 | 顶层虚拟化仍卡顿或字形改变；先原型，整段路径保留 | 长单段、长代码行、公式混排 |
| 缓存键缺少父/邻接依赖 | 高 | 编号、缩进、间距或字体沿用旧值；失效矩阵与完整代次 | 列表移动、字号、语言、公式字体 |
| 缓存增加峰值内存 | 中高 | 新旧快照叠加；共享、字节预算和在途任务上限 | 快速编辑/撤销、导出同时编辑 |
| 扩展默认假设失效 | 中 | 未声明稳定输入的功能显示过期；默认全量重建 | 附加功能、高亮延期、故障隔离 |
| 优化只在单一语料有效 | 中 | LF 普通段落掩盖 CRLF/结构成本；完整矩阵和绝对耗时 | 一大块/很多小块、三种换行 |

P1/P2 风险集中在局部算法等价，可以小步交付；P3 风险集中在 UI 几何一致性；
P4/P5 涉及全链路快照契约，是 10 MiB 低输入延迟的最大不确定性。
